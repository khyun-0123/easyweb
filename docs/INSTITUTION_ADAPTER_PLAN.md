# 기관별 의미 보정 구현안

2026-10-18 · RUN-006의 다운로드 안전 수정 이후 실행할 개발 계획. 아직 구현·성공 결과가 아니다. [작업명세](WORK_SPEC.md)의 5개 기관 파일럿 범위와 [RUN-005 실패 진단](evidence/run005/v8-failure-diagnosis.md)을 따른다.

범용 규칙만으로 새 v8 자료의 교육·연금 설명·대학 IT 문서 의미를 충분히 구분하지 못했다. 기관별 보정은 실제 원본 제어의 의미 근거만 추가한다. action·href·권한·위험 명령 판정을 변경하지 않는다. 기존 50페이지와 모든 최초 실패는 보존한다.

## 구현 순서

1. 별도 `institution-evidence.ts`를 만들고 `classify(candidates, { mode: 'generic' | 'institution' })`로 비교한다. 같은 v0.7 다운로드 안전 수정 소스가 양쪽 기준이다. 공통 입력 보호·가시성·위험 명령·URL 검사 다음에 보정을 적용한다. 분류 결과 뒤에서 후보를 합쳐 이미 제외한 위험 제어를 되살리지 않는다.
2. 근거에는 adapter/version/rule, category, reading 과제 여부, 65 또는 70점의 고정 점수, 의존 요소와 fingerprint를 기록한다. 모호하면 보정을 포기하고 기존 범용 경로를 따른다. UI에는 사용자에게 필요한 분류·원본 이름만 표시한다. 평가 보고서·파일명에는 mode와 adapter version을 남긴다.
3. `isCandidateCurrent()`에서 규칙 재성립·fingerprint·의존 노드 동일성을 확인한다. 같은 ID로 노드를 교체한 경우도 낡은 카드를 차단한다. 제목·패널·컨테이너 근거는 로컬 관계로 제한하고 입력값·본문 전체를 fingerprint에 넣지 않는다. 컨테이너별 계산은 한 분석/검사 안에서 재사용해 반복 전체 스캔을 피한다.
4. 합성 반례와 현재 노출된 50페이지를 같은 소스로 generic/institution 비교한다. 최초 최대 6개와 추가 메뉴 합집합은 별도로 보고한다. 그 뒤 다섯 기관 모두의 새 페이지를 독립 관찰자가 작성·동결하고 첫 결과를 보존한다.

## 첫 보정 범위

| 기관·경로 | 반드시 필요한 원본 근거 | 의미 |
| --- | --- | --- |
| `www.safekorea.go.kr`, `/safekorea-kor/edtr/` | 교육훈련 본문 제목과 로컬 안내 메뉴의 관계, 또는 실제 펼침 버튼과 같은 묶음의 내용 패널 | 교육 계획·참고 자료·교육 개요를 help로 읽음. 공유·신청·제출 제어 제외 |
| `www.nps.or.kr`, `/pnsinfo/ntpsklg/` | 실제 설명 탭 컨테이너의 fragment 링크와 유일한 같은 묶음 패널, 고정 탭명과 제목의 일치 | 설명 읽기를 help로 읽음. 숨은 패널 내부의 숨은 제어를 추천하지 않음 |
| `www.smu.ac.kr`, `/kor/life/` | 게시판 제목·문서 제목 구조와 문서 링크, 구체적인 문서 목적 | 작업·장애·중단 통지는 notice, 설치 방법·사용 절차는 help. 샘물 등 주제 배지만으로 academic 판정하지 않음 |

천안시·도서관은 첫 보정에서 기존 범용 경로를 유지한다. 다섯 기관 전체에서 적용/미적용과 회귀를 보고한다. 호스트·경로만으로 분류하거나 `안내`만 있는 문서를 강제로 보정하지 않는다. `articleNo`·문서 번호·불투명 메뉴 query 값·평가 ID·원본 순서를 정답 조회표로 사용하지 않는다.

## 필요한 검증

- 낯선 제목·ID·순서의 교육 메뉴, 설명 탭, 유지보수 공지, 설치 안내. 기관 주제와 문서 목적을 분리한다.
- 위장 호스트·미지원 경로·관계없는 이웃 제목·없거나 중복된 fragment 대상·제출 버튼·모호한 문서 반례.
- 입력 canary·위험 명령 제외, JS/인증/다운로드의 기존 action 유지, 의존 제목·컨테이너·패널·노드 교체 후 stale 차단.
- 같은 50페이지의 양쪽 mode 회귀와 성능. 이미 읽은 v8 재평가는 개발 결과로만 기록한다. 새로운 독립 평가와 실제 사용자 실증은 따로 판정한다.

현재 순위 정책과 품질 기준은 유지한다. 기관별 보정의 개선 여부는 구현 후 실제 비교로 판단하며, 이 계획이나 알려진 페이지 통과만으로 S07을 완료 처리하지 않는다. 컴퓨터 유즈·native UI·기존 브라우저 조작은 사용하지 않는다.
