# EasyWeb 수동 확인실

**실제 수동 결과: NOT_RUN.** 이 확인실은 S06의 실제 VoiceOver 발화·최종 브라우저 확대와 S08의 설치 실행·복구를 재현하기 위한 합성 페이지다. [설치 안내](INSTALL.md)에 따라 같은 최종 패키지를 설치한 뒤, 사용자가 시간이 있을 때 직접 실행한다. 컴퓨터 유즈 자동화는 재개하지 않는다.

## 열기와 기록

이미 사용하는 4173 서버나 브라우저를 바꿀 필요 없이 프로젝트 터미널에서 별도 서버를 시작한다.

4183 서버가 이미 실행 중이면 아래 명령을 다시 실행하지 않고 링크만 연다. 이 확인실은 자동으로 창을 열거나 사용자의 컴퓨터를 조작하지 않는다.

```bash
cd /Users/khyun_03/easyweb
npm run demo -- --port=4183
```

[http://127.0.0.1:4183/manual-check.html](http://127.0.0.1:4183/manual-check.html)을 열고 **설치한 EasyWeb 도구 모음 버튼**으로 실행한다. 이 페이지에는 데모 주입 버튼이 없으며 자동으로 EasyWeb을 실행하지 않는다. 최초 실행 전에 확장 로드 경로·버전, 패키지 SHA256, OS·Chrome 버전·날짜를 아래에 적는다. 검사 중 빌드가 바뀌면 이전 기록과 새 기록을 나눈다.

| 환경 | 실제 값 |
| --- | --- |
| 시험 일시·익명 확인자 | UNKNOWN |
| OS·Chrome 버전 | UNKNOWN |
| 확장 버전·로드 경로·ID | UNKNOWN |
| 설치한 ZIP SHA256 / content.js SHA256 | UNKNOWN |
| 시작 브라우저 확대·VoiceOver 설정 | UNKNOWN |
| 도구 모음 클릭 / 실제 배정 단축키 | UNKNOWN |

페이지는 정적인 가짜 버튼·로컬 링크만 사용한다. 입력창·로그인·제출·다운로드·외부 통신·기록 저장이 없다. 원본 버튼을 직접 누르면 화면의 합성 실행 횟수만 늘어난다. 새로고침하면 횟수와 모든 예약이 초기화된다.

## 순서와 예상 결과

1. **기본 키보드와 복귀:** 아무 예약 없이 도구 모음으로 연다. 처음 초점은 `원본 화면 보기`다. Tab/Shift+Tab으로 다시 찾기·통합검색 버튼·공지사항 링크를 양방향 순환한다. Esc로 닫고 다시 연다. 쉬운 화면이 중복되지 않고 원본 초점·스크롤이 돌아오는지 확인한다. Mac에서 Tab이 일부 제어를 건너뛴다면 Chrome/macOS의 키보드 탐색 설정을 기록하고, 실제 사용하는 설정에서 다시 확인한다.
2. **실제 VoiceOver:** 사용자가 음성을 들을 수 있을 때 VoiceOver를 켠다. 모달 제목·설명, 각 카드의 링크/버튼 역할과 원본 메뉴 이름을 듣는다. `다시 찾기` 뒤 탐지 상태가 읽히고 초점이 유지되는지 확인한다. 실제 들린 짧은 문구를 결과표에 적는다. 접근성 트리에 이름이 있다는 사실은 음성 통과의 대체가 아니다.
3. **원본 안내 성공:** 통합검색 카드를 선택한다. 모달은 닫히고 원본 통합검색 버튼에 초점·강조가 있어야 한다. 위치 안내 상태가 실제로 읽혀야 한다. **이 시점 합성 실행 횟수는 0**이다. 안내를 닫고 원본 통합검색을 직접 누르면 1이 된다. 이는 가짜 횟수 증가일 뿐 검색 완료가 아니다.
4. **오래된 후보:** 원본에서 `시험 초기화` → `10초 뒤 메뉴 바꾸기`를 누른 뒤 **10초 안에 확장을 열고 12초 정도 기다린다.** 원본 통합검색이 자료 검색으로 바뀌면 쉬운 화면에 원본 변경·다시 찾기 안내가 나와야 한다. 이전 카드로 원본 동작을 실행하면 안 된다. 다시 찾기로 자료 검색 카드가 나타나고 초점·상태 알림을 사용할 수 있어야 한다. 이 경로는 오래된 후보 차단이며, 원본 안내의 `changed` 오류를 강제로 만드는 경로는 아니다.
5. **가려짐 실패:** 새로고침 → `10초 뒤 가림막 놓기` → 10초 안에 확장 열기 → 12초 정도 기다린다. 가림막은 원본을 가리고 쉬운 화면의 모달 뒤에 남는다. 통합검색 카드를 누르면 **성공 대신 ‘다른 창에 가려져 있어요’ 오류**, 안내 닫기 버튼 초점, 실제 VoiceOver 오류 안내를 확인한다. 합성 실행 횟수는 0이어야 한다. 안내 닫기/Esc 후 `가림막 치우기`를 누르거나 생성 후 45초까지 기다린다. 확장을 다시 열어 통합검색 안내가 성공하는지 확인한다. 페이지 새로고침도 언제든 초기화한다. 가림막 자체는 키를 가로채거나 초점을 자동으로 바꾸지 않는다.
6. **실제 확대:** 브라우저 메뉴의 확대 표시를 직접 200%, 400%로 바꿔 각각 다시 연다. 가로로 잘려 주요 제어에 접근할 수 없는지, 모든 카드·닫기·다시 찾기를 키보드로 사용할 수 있는지, 초점과 읽는 순서가 이해되는지 확인한다. CSS 너비 변경·기기 모드·스크린샷 확대를 브라우저 확대 통과로 적지 않는다. 확인 뒤 원래 확대를 복원한다.
7. **설치 실행과 복구:** 도구 모음으로 열기 → 같은 버튼으로 닫기 → 재실행, Chrome에 실제 배정된 단축키로 열기/닫기를 각각 확인한다. 기본 제안은 `Alt+Shift+E`(Mac Option+Shift+E)이며 충돌·미배정 여부는 `chrome://extensions/shortcuts`에서 직접 확인한다. 공지사항 카드로 같은 로컬 확인실의 ‘다음 화면’에 직접 이동 → 확장 재실행 → 페이지 새로고침 → 재실행 → 뒤로 가기를 확인한다. 마지막으로 `chrome://extensions`에서 실행 제한 오류를 확인하고 이 로컬 페이지로 돌아와 도구 모음 재실행이 정상인지 확인한다. 오류 뒤 영구적으로 실행이 막히거나 낡은 안내가 남으면 실패다.

VoiceOver와 확대·키보드 설정은 시험 전 상태로 되돌린다. 서버는 해당 터미널에서 Ctrl+C로 종료한다. 다른 기존 서버·브라우저 창을 종료할 필요는 없다.

## 이 확인실이 증명하는 범위

`tests/manual-check.spec.mjs`의 헤드리스 검사는 **이 확인실의 장치**가 실제 빌드의 경로에 연결되는지 검사한다. 예약 변경이 원본 후보를 무효화하는지, 가림막이 실제 원본 hit-test를 가려 실패 안내를 만드는지, 가림막 수동·45초 자동 제거 후 안내가 복구되는지, 안내 자체가 원본 버튼을 클릭하지 않는지, 로컬 링크와 재실행용 다음 화면이 동작하는지 확인한다. 이 검사에서 브라우저에 빌드 코드를 직접 주입한 결과는 네이티브 도구 모음·원래 Manifest·실제 음성·실제 확대 통과 증거가 아니다.

```bash
npx playwright test tests/manual-check.spec.mjs --reporter=list
```

시험 장치는 의도한 상황만 만든다. iframe·닫힌 Shadow DOM·실제 기관 팝업이나 속성 없는 위임 이벤트의 완전한 보존을 검증하지 않는다. 이 로컬 한 페이지의 성공만으로 S08의 **고정된 5개 실제 기관 사이트 실행 기록**을 대신할 수 없다. [접근성 문서](ACCESSIBILITY.md), [설치 안내](INSTALL.md), [지원 범위](SUPPORT_MATRIX.md)의 남은 항목도 확인해야 한다. [1인 사전 시험](PRETEST.md)과 정식 6~8명 실증 결과를 합산하지 않는다.
