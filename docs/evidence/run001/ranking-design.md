# RUN-001 S04 분류·추천 규칙

작성일: 2026-10-17. 이 문서는 범용 엔진 변경과 합성 회귀 검증만 기록한다. 사이트별 정답표 평가와 실제 사용자 과제 결과는 별도 증거다. 아래 테스트 통과를 S04·S07 전체 인수 완료로 해석하지 않는다.

## 분류 근거

- 고정된 후보 문구와 명시적 검색 제어를 URL 추정보다 우선한다. 한국어·영어 문구를 사용하며 Unicode NFKC 정규화와 영어 단어 경계로 `Research`가 `search`로 잡히는 것을 막는다. `자주하는질문`, `뷰어 다운로드`, `민원실 안내`, `상담 안내`, `새소식` 같은 일반 변형을 포함한다.
- `Q&A/Q & A`, `뷰어프로그램 안내`, `search tip/tips`도 이용 안내다. 분류용 후보 문구 안에서만 `_/-`를 단어 구분자로 처리하여 고정 접근성 이름 `search_tip/search-tip`을 해석한다. 원본 후보 문구·URL·JS href·동작 메타데이터는 바꾸거나 추가 해석하지 않는다. `Research_tip`은 검색으로 잡히지 않으며 실제 text 검색 입력의 검색 의미는 유지한다.
- `문의`는 공백·문장부호로 구분된 실제 문의 단어, `문의하기/문의처/문의사항` 또는 `고객문의/이용문의` 같은 정해진 합성어에서만 읽는다. `방문의 해/방문의날/영문의 해설`의 부분 문자열을 이용 안내로 오분류하지 않는다. 임의의 새로운 합성어를 모두 인식한다는 뜻은 아니다.
- `input type=text`와 type이 없는 기본 text 입력도 안전한 후보 이름이 `검색/search`를 명시하면 검색 제어 근거를 갖는다. 안전한 이름을 전달하는 분석기와 함께 B02를 보완한다. `.value`는 읽지 않는다. 이 의미 근거는 같은 문구의 submit 버튼보다 검색 입력 위치를 먼저 남길 수 있지만 기존 주요 메뉴 우선·분류 다양성·개수 제한은 유지한다.
- `검색방법/검색 안내/search guide`는 검색 실행과 구별하여 이용 안내로 분류한다. 명시적 검색 입력 제어 자체는 검색 의미를 유지한다. 같은 점수라면 구체적인 도움말 문구, 명시적인 신청·접수·예약 목적을 넓은 학사 분야보다 우선한다. `수강신청`은 신청, `수강 안내/등록금 조회`는 학사, `예약 도움말`은 이용 안내가 된다. 별도 가산점은 없다.
- B03의 URL 단독 지원은 **주요 메뉴 + HTTP(S) 일반 이동 + 완전한 기능 endpoint**로 한정한다. `/auth/login.do`, `/search/index.html`은 허용하지만 `/login-news`, 본문·하단의 모호한 URL 단독 링크는 허용하지 않는다. 파일 확장자와 일반적인 `index/list/main` 끝 경로만 정규화하며 사이트별 경로 예외는 없다.
- `계정 → /login`이 본문에만 있으면 계속 제외한다. 기존 최대 40점 문제를 모든 URL 일치 후보의 일괄 승격으로 고치지 않고, 지원 조건을 명시한 정책이다.
- `더보기`, `바로가기`, `자세히 보기`, `more/read more/open`처럼 정확히 모호한 문구에는 선택적 `sectionLabel`을 보조 근거로 사용한다. 주변 제목도 `공지사항`, `통합공지/주요 공지사항/전체공지`, `FAQ`, `수강신청` 같은 짧고 정확한 기능 제목이어야 한다. 알려진 endpoint가 다른 분류를 가리키면 제목 근거를 사용하지 않는다. `공지사항이 달라집니다` 같은 문장에는 적용하지 않는다.
- 장식·브랜드 접두어가 붙은 `… 더보기/… read more`는 24자 이하이며 **정확한 기능 제목과 같은 분류의 완전한 endpoint가 함께** 있을 때만 제목 근거를 쓴다. 접두어 자체에는 사이트별 사전을 적용하지 않는다.
- 본문 article 안의 일반 이동 링크와 `news/article/story/press` 아래의 개별 글 경로를 제외한다. 완전한 공지 endpoint에 `view/detail/read` 명령 또는 명시적인 article/post 식별자가 있으면 개별 공지 문서로 보아 제외한다. 공지 목록은 유지한다. 기능명이 글 제목에 나타나는 것만으로 학사·등록금 업무를 만들거나 본문 URL 규칙을 확장하지 않는다. 실제 검색 제어는 article 안에서도 후보가 될 수 있다.
- 위험 문구뿐 아니라 위험 목적지 경로와 지정된 명령 쿼리(`action`, `mode` 등)도 확인한다. 로그아웃·탈퇴·삭제·결제·납부·구매·최종 제출은 제외한다. 검색어 등 임의 쿼리 값은 읽지 않는다. 잘못된 URL과 비 HTTP(S) URL은 예외 없이 건너뛴다.
- 하단은 낮은 우선순위다. URL 단독 또는 주변 제목만으로 승격하지 않으며, 짧은 직접 문구와 완전한 endpoint가 함께 있을 때 보조 후보가 될 수 있다.

점수는 규칙 우선순위이며 성공 확률이나 통계적으로 보정된 신뢰도가 아니다.

| 근거/보정 | 점수 |
| --- | ---: |
| 직접 문구 | 60 |
| 문구가 없는 명시적 검색 제어 | 62 |
| 제한된 주변 기능 제목 | 48 |
| 허용 조건을 만족한 URL 단독 | 45 |
| 직접 문구와 검색 제어 일치 | +12 |
| 다른 근거와 같은 분류 endpoint 일치 | +12 |
| 주요 메뉴 / 본문 / 하단 | +15 / 0 / -25 |
| 14자 이하 / 37자 이상 | +10 / -15 |
| 채택 기준 | 55 이상 |

예: 주요 메뉴의 URL 단독 후보는 짧은 문구일 때 70점, 본문의 직접 문구도 70점, 주요 메뉴의 직접 문구는 85점이다. 본문의 짧은 `더보기`+정확한 기능 제목은 58점이며 endpoint까지 일치하면 70점이다. 하단의 짧은 직접 문구+endpoint는 57점이다.

## 중복과 선택

1. 점수, 영역, 문구 길이, 정규화 문구, 목적지, 분류, 동작, 원본 ID의 고정 순서로 비교한다. 관계없는 DOM 순서로 동점의 선택이 바뀌는 것을 줄인다.
2. 이동은 정규화된 전체 URL, 위치 안내는 실제 원본 요소 identity로 중복을 제거한다. **분류와 별개**이므로 같은 URL이 다른 분류 문구로 반복되어도 하나만 남는다. 경로의 쿼리·앵커는 원래 목적지를 구별할 수 있어 보존하며 추적 파라미터를 임의로 제거하지 않는다.
3. 분류마다 최상위 하나를 먼저 고른다. 6칸이 남으면 별개 목적지/제어의 다음 중요 기능을 채우되 분류당 최대 2개, 전체 최대 6개다.
4. 같은 문구라도 별개의 위치 안내 제어는 임의로 하나로 합치지 않는다. 반대로 같은 원본 제어가 여러 분류로 들어와도 하나만 남는다.

분류가 하나뿐인 페이지라도 최대 2개로 제한한다. 완전히 같은 점수·문구·URL·분류·동작이고 원본 ID도 없는 별개 제어는 추가 의미를 추측하지 않으므로 완전한 identity 수준 순서 보장은 없다. 이는 내용이 다른 후보의 결정적 정렬과 구별한다.

## 재현 및 결과

초기 구현은 사이트 fixture를 열지 않고 합성 예시로 검증했다. 후속 보정에서는 허용된 **calibration 결과 JSON 두 개만** 읽고 공통 누락·오분류를 합성 회귀로 재현했다. 페이지 fixture와 holdout 데이터·결과·성능 자료는 열지 않았다. 부모 작업자가 전달한 개발용 관찰도 일반적인 주변 제목·짧은 접두어 문구 요구사항으로 반영했다. 사이트별 보정 규칙은 추가하지 않았다.

초기 12개 합성 테스트는 동결 기준선 1 통과/11 실패, 첫 수정본 12 통과였다. 첫 후속 보정은 새로운 독립 합성 회귀 4개를 추가한 **동일한 16개 테스트**로 변경 직전 12 통과/4 실패, 변경 후 16 통과를 확인했다. 동결 기준선도 그 16개로 다시 비교했다. 이후 구체적으로 재현된 문의 오탐·text 검색 의미 누락만 회귀 2개로 추가했다. 동일한 18개 테스트에서 이 두 수정 전은 16 통과/2 실패, 수정 후는 18 통과였다. 마지막으로 Q&A·뷰어프로그램 안내·기계식 검색 팁 이름 회귀 1개를 추가한 **동일한 최종 19개 테스트**에서 변경 전 18 통과/1 실패, 변경 후 19 통과를 확인했다. text 검색 회귀는 value getter가 예외를 던지도록 하여 입력값 비접근도 확인한다.

회귀는 URL 단독·의미 기반 검색·text/기본 검색 입력의 순위·모호한 문구·기사/공지 문서 오탐·한국어/영어/전각문자·문의와 방문의/영문의 구별·FAQ/사용법/도움말/새소식 변형·신청 목적 동점·위험 URL/문구·잘못된 URL·하단·분류 간 URL 중복·별개 동일 분류 기능·동작 제어 identity·쿼리/앵커 보존·무관한 DOM 순서 변화를 포함한다. 이 변경에서 전역 빌드·다른 테스트·실제 사이트 클릭은 실행하지 않았다. 통합 검증과 변경 후 calibration 재평가는 부모 작업이 수행한다.

처음 읽은 calibration 보고서(2026-10-17T14:34:57Z)는 정확도 30/32(93.75%), 기대 기능 재현 17/30(56.67%)였다. 동결 기준선 calibration은 21/21(100%), 11/30(36.67%)였다. 이는 읽은 당시 개발용 보고서의 값이며 **후속 변경의 개선 수치가 아니다**. 변경 후 결과로 덮어 쓰거나 holdout 검증으로 표현하지 않는다.

전체 작업 경과 시간과 실제 소비 토큰은 UNKNOWN이다.

## 한계와 다음 판정

- 한국어·영어의 제한된 명시적 사전이며 임의 언어·축약어·모든 기관 용어를 지원하지 않는다.
- 기사 경로와 article 구조의 보수적 제외는 실제 서비스가 그 구조에 배치된 경우 누락을 만들 수 있다. URL substring 승격으로 재현율을 올리지 않는다.
- 공지 읽기 자체가 기대 과제인 경우에도 개별 공지 문서 제외 정책은 누락을 남긴다. 이번 수정은 글의 주제를 학사 업무로 오분류하는 문제를 줄이는 선택이며 과제 통과를 맞추기 위한 공지 기사 승격은 하지 않았다. 별도의 문서 읽기 분류가 필요하면 독립 요구사항·회귀·평가로 설계해야 한다.
- 주변 제목은 부모 분석기가 입력 내용을 제외하여 추출한 값만 사용한다. 합성 엔진 테스트는 제목 추출기의 개인정보 보호를 대신 검증하지 않는다.
- 정적 위험 단어 검사는 임의 JS/위임 이벤트의 의미를 증명하지 않는다. 자동 실행 경계와 원본 연결은 별도 S03/S05 정책이 필요하다.
- 독립 사이트 평가 수치가 낮으면 이 테스트 통과와 별도로 미달을 기록한다. 평가용 페이지에 맞춘 추가 조정 후 같은 결과를 독립 검증으로 부르지 않는다.
