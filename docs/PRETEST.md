# EasyWeb 1인 사전 시험 · 약 5~10분

상태: **준비 완료 / 실제 시험 미실시**. `PILOT01`은 기록에 사용할 익명 코드이며 참여·성공을 기록한 값이 아니다. 정식 6~8명 [사용자 실증](USER_STUDY.md)은 계속 **NOT_RUN**이다.

이 사전 시험은 설치한 후보에서 화면이 열리는지, 메뉴 이동 방식이 이해되는지, 잘못 안내하거나 돌아오기 어려운 곳이 있는지 찾는 용도다. 같은 과제를 원본과 EasyWeb에서 두 번 수행하거나 속도를 비교하지 않는다. 결과를 정식 실증의 참여자 수·사이트별 짝 관찰·성공률·시간 감소율에 합산하지 않는다. 사전 시험을 마쳐도 제품 인수 통과를 뜻하지 않는다.

## 시작 전

시험할 버전은 **v0.7.0 개발 후보**다. 실제 ZIP 경로·압축을 푼 폴더명·최종 해시·최종 검사 결과는 [RUN-006 보고서](RUN_006_REPORT.md)에서 확인한다. 저장소에서 설치한다면 `/Users/khyun_03/easyweb/dist`를 사용한다. 새 독립 v8도 품질 목표 미달이다. 다운로드 식별과 현재성 반례를 수정해 현재 완료는 5/10이며,, 실제 VoiceOver 발화·실제 브라우저 확대·현재 버전의 네이티브 설치 경로·사용자 실증은 미검증이다. [설치 안내](INSTALL.md)에 따라 빈 Chrome 프로필에서 설치한다. 설치 시간은 아래 5~10분에 포함하지 않는다. v0.3.0의 자동 검사·기존 공개 과제 관찰은 [RUN-002 과거 기록](RUN_002_REPORT.md)으로 구별한다.

메뉴 전환과 보조기술·확대·복구를 확인할 때는 [수동 확인 안내](MANUAL_CHECK.md)와 <http://127.0.0.1:4183/manual-check.html>를 사용한다. 이 로컬 점검은 아래 다섯 공개 과제나 정식 사용자 실증의 결과에 합산하지 않는다.

[결과 서식](../evaluation/pretest/result-form.blank.md)을 복사해 두고 사용한 빌드·Chrome 버전만 적는다. 모르는 값은 `UNKNOWN`으로 남긴다. 이름·계정·연락처는 쓰지 않는다. 화면 녹화나 스크린샷은 필수가 아니며, 남기려면 공개 화면만 사용한다.

## 한 사이트에서 할 일

1. 아래 **시작 페이지**를 열고 로딩이 끝나면 도구 모음의 EasyWeb을 누른다.
2. 처음 보이는 메뉴는 최대 6개다. 필요한 메뉴가 없으면 **다른 메뉴 보기**를 살펴보고 **이전 메뉴**로 돌아올 수 있다. 과제에 맞는 카드를 한 번 선택한다. **일반 링크 카드는 공개 목적지로 바로 이동**한다. JavaScript·SSO·다운로드 등 동작을 대신 실행하기 어려운 제어는 **원본 위치 안내**로 돌아가며, 원본 메뉴가 보이는지 확인한 뒤 멈춘다. 안내 뒤 원본 제어를 추가로 누르지 않는다.
3. 목적지가 맞았는지, 이동 방식이 예상과 같았는지 기록한다. 카드가 나왔다는 사실만으로 도달을 표시하지 않는다. 공개 페이지 도달 과제에서 원본 제어까지만 안내됐다면 `미도달`과 `원본 위치 안내`를 함께 적는다.
4. 같은 탭에서 바로 이동했다면 Chrome 뒤로 가기로 시작 페이지에 돌아온다. 새 탭/창이 열렸다면 그 탭/창을 닫고 시작 탭으로 돌아온다. 원본 위치 안내인 경우 `안내 닫기` 또는 Esc로 안내를 닫는다. EasyWeb을 다시 열었다가 `원본 화면 보기` 또는 Esc로 닫는 동작은 전체 시험 중 한 번만 더 확인한다.

사이트당 약 1분 정도만 살펴본다. 90초가 지나도 못 찾겠으면 `미도달`을 적고 다음 사이트로 넘어가도 된다. 전체 10분이 되거나 불편하면 멈춘다. 남은 과제는 `미실시`로 남기며, 반복해서 성공한 결과로 이전 실패를 덮어쓰지 않는다. 대략적인 진행 시간은 안내용이며 성능 지표를 계산하지 않는다.

## 멈추고 기록할 경우

로그인·인증·개인정보 입력·실제 신청·폼 제출·결제·삭제·파일 다운로드·프로그램 설치는 하지 않는다. 그런 화면이나 예상하지 못한 창이 열리면 추가 진행 없이 닫고 사건만 적는다. 보안 경고·서버 차단은 우회하지 않고 `접근 차단`으로 남긴다.

엉뚱한 페이지, 가려진 원본, 없는 카드, 이해하기 어려운 문구, 원본 복귀 실패도 유용한 결과다. 입력한 내용이나 비공개 화면을 기록하지 말고 `카드 없음`, `다른 메뉴`, `새 창 예상 못함`처럼 짧은 사건 설명을 쓴다. 메뉴를 못 찾은 사용자의 잘못으로 판단하지 않는다.

## 결과를 남기는 방법

[간단 결과 서식](../evaluation/pretest/result-form.blank.md)의 다섯 줄과 마지막 질문 세 개만 채워 전달해도 된다. 실행하지 않은 항목은 `미실시`, 확인하지 않은 항목은 `모름`으로 쓴다. 진행자가 구조화해 기록할 때는 헤더만 있는 [빈 관찰 CSV](../evaluation/pretest/observations.blank.csv)를 복사해 사용한다. 결과는 `evaluation/pretest/`에 별도 보관하고 정식 `evaluation/study/observations.real.csv`나 분석 CLI에 넣지 않는다.

CSV는 실제 시도한 과제만 한 행씩 기록한다. `pretest_id=PRETEST-001`, `participant_id=PILOT01`, `task_id=PRE01`~`PRE05`를 사용한다. `outcome`은 `reached/not_reached/blocked/stopped`, `observed_action`은 `direct_navigation/original_guidance/no_card/no_ui/not_attempted`, 이해·복귀 응답은 [plan.json의 recording](../evaluation/pretest/plan.json)을 따른다. 모르는 빌드/해시는 `UNKNOWN`으로 쓰며 실제 관찰 시각만 적는다. 미실시 과제에는 측정 행을 만들지 않는다. `issue_code/evidence_ref/observer_note`에는 공개 사건과 로컬 근거만 남긴다.

사전 시험에서 배운 위치는 이후 정식 실험의 학습 효과가 될 수 있다. `PILOT01` 기록을 정식 참여자 코드로 바꿔 재사용하지 않는다. 같은 사람이 정식 실증에 참여하려면 사전 노출과 새 배정을 별도 계획·기록하고, 이 사전 기록을 합산하지 않는다.

준비 자료의 구조 확인과 실제 사용 결과는 구별한다. 현재 실제 관찰은 **0건**, 사전 시험은 **NOT_RUN**, 정식 실증도 **NOT_RUN**, 제품 인수는 **NOT_EVALUATED**다.
