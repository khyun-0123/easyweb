# RUN-001 · 첫 개발 묶음 결과

버전: **0.2.0 개발 후보** · 시작: 2026-10-17 23:26:55 KST · 검증·패키지 기록 마감: 23:55:55 KST · 경과: **29분** (이후 로컬 커밋·인계 포함 약 30분)

첫 4시간 묶음의 목표인 입력 보호 수정, 정답 기준선 구축, DOM·분류·중복 개선을 구현했다. **S01~S04, 4/10 단계 완료**다. 4시간은 최대 작업 창으로 사용하며, 범위가 먼저 끝나면 검증·기록 후 종료한다. 단계 수는 전체 공수의 40%라는 뜻이 아니다.

실제 입력·캐시 입력·출력·추론·하위 작업자 소비 토큰 및 비용은 **UNKNOWN**이다. 계획상 50,000 생성 작업 토큰을 실제 계정 사용량으로 환산하지 않았다.

## 정답 자료와 전후 비교

상명대·천안시·국민안전24·국민연금공단·국립중앙도서관의 **15개 공개 페이지, 기대 기능 45개 그룹, 공개 과제 15개**를 고정했다. 정부24 접근 차단으로 같은 유형의 국민안전24를 사용한 경과를 보존했다. 각 사이트 2페이지는 개발용, 1페이지는 보류용이다. 정답은 제품 분류기를 보지 않은 별도 관찰에서 먼저 작성했다.

자료는 실제 메뉴 일부를 재구성한 축약 fixture다. 전체 사이트 복사본이나 이벤트 구현이 아니다. v1.1에서는 도서관 한 제어의 원본 `href="#"`·inline 클릭 존재 표식을 바로잡았고, 이전 fixture·변경 사유·해시를 남겼다. 정답·과제·분리는 그대로 유지하고 전후 엔진 모두 같은 자료로 평가했다. [데이터 설명](../evaluation/README.md)

| --- | --- | --- |
| 올바른 추천 / 전체 추천 | 21/21 (100%) | 37/37 (100%) |

기준선 전체 15페이지는 올바른 추천 31/31, 핵심 기능 18/45(40%), 과제 제어 추천 3/15다. **현재 엔진의 보류용 5페이지 평가는 수행하지 않았다.** 보류 자료에 맞춰 규칙을 수정한 결과를 독립 평가라고 부르지 않도록 S07에 남겼다.

누락한 7개 기대 기능을 정답에서 제거하지 않았다.

- 천안시의 `소식알림`, `무료상담운영`: 현재 고정 문구·URL의 의미 근거 부족.
- 국민안전24 두 페이지의 하단 `Q&A`: 하단 후보에 적용한 보수적 URL 근거 조건으로 제외.

- 국민연금공단 점심시간 안내, 상명대 중간고사 안내의 개별 게시글: 현재 서비스 메뉴와 상세 문서를 구별하는 정책으로 제외. 정답의 문서 도달 과제를 충족하지 못하는 실제 한계다.

S07 전체 재현율 85%·사이트별 75%·실제 과제 15/15 목표는 아직 미달/미검증이다. S04의 구현·전후 비교 완료와 제품 최종 품질 통과를 구별한다.

## 검증과 증거

최종 타입 검사·빌드 통과, 자동 테스트 **46/46 통과**. 원래 11개에서 개인정보·동적 변화·분류·중복·액션·강조 복원·데이터/지표 검증을 추가했다. [전체 테스트 로그](evidence/run001/tests.log) · [타입 검사](evidence/run001/typecheck.log). 환경은 macOS/Darwin arm64, Node 26.0.0, Playwright 1.64.1, Chromium 156.0.8078.4다.

상명대 실제 공개 홈페이지는 HTTP 200, 후보 87개·분류 후보 11개에서 검색·신청/조회·학사정보·로그인·통합검색·공지사항 6개 카드를 표시했다. 페이지 오류는 0개였다. 사이트 방문·탐지·표시만 검사했고 실제 로그인·검색·신청·도구 모음 실행은 하지 않았다.

합성 1천 제어 분석 10회 p95는 **60.4ms**였다. [환경·10회 원시값](evidence/run001/analyzer-performance-smoke.json). S07의 분석 300ms 목표보다 낮은 smoke 결과이며, 실제 사이트의 대표 성능·실행부터 화면 준비까지의 1초 목표를 검증한 결과는 아니다.

## 남은 작업과 다음 시작점

다음은 **S05의 액션 사례표와 원본 복귀 검증**이다. 현재 단순 URL 복사는 사이트의 `addEventListener` 위임·JavaScript `element.onclick`·SPA 라우터 등 원본 이벤트를 모두 재현하지 못한다. inline 속성이 없는 팝업 링크를 일반 이동으로 분류하는 합성 재현이 남아 있다. 실제 확장의 isolated world에서 관찰할 수 있는 정보도 확인한 뒤 정책을 정해야 한다. 팝업에 가려진 대상, 불투명한 다운로드 URL, 새 창·이름 있는 창, 열린 Shadow DOM·iframe 지원 제약을 포함한다.

이어 S06에서 대비 B07·VoiceOver·확대/강제 색상/키보드 상태를 확인하고, 규칙 고정 후 S07에서 보류용 평가·실제 15개 공개 도달·화면 준비 p95를 검증한다. S08의 **배포 Manifest 그대로의 실제 도구 모음 → activeTab 경로**, S09의 실제 대상 사용자 실증도 미실시다. localhost 권한을 추가한 테스트 복사본 통합 검사는 별도 증거이며 S08 통과가 아니다.

개발 ZIP과 로컬 Git 체크포인트는 복구·검토용이다. v1.0 릴리스 인수 통과나 Chrome 웹 스토어 공개를 뜻하지 않는다.

- [개발용 확장 ZIP](../output/easyweb-v0.2.0-dev.zip) · [ZIP SHA256](../output/SHA256SUMS) · [빌드 파일 해시](evidence/run001/build-manifest.json). ZIP 무결성과 내부 Manifest 0.2.0을 확인했다.
- 로컬 Git 체크포인트 태그: `run-001-v0.2.0-dev`. 원격 저장소 생성·push·게시 없음.
- 기존 로드형 확장은 Chrome 확장 관리에서 새로고침하고 대상 페이지를 새로고침한다. 새 설치는 ZIP을 풀고 내부 `easyweb-v0.2.0-dev` 폴더를 압축해제 확장으로 선택한다. 프로젝트에서는 `dist/`를 선택해도 된다.
