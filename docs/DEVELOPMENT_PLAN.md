# EasyWeb 개발 진행 계획

> 이 문서는 초기 v0.1 구현 계획과 결과 기록입니다. 이후 개발의 기준은 [v1.0 작업명세서](WORK_SPEC.md), [진행표](PROGRESS.md), [시간·토큰 예산](EXECUTION_BUDGET.md)입니다. 초기 단계 번호와 v1.0의 S01~S10 번호는 서로 다른 계획입니다.

기준일: 2026-10-17 (한국 시간) · 현재 단계: 1차 MVP 구현 및 검증

## 제품 목표와 근거

기획 자료: [모두의창업 EasyWeb](../모두의창업_EasyWeb.pdf), 특히 2~3쪽 기능 설계와 5~6쪽 개발·검증 계획.

사용자가 현재 페이지에서 필요한 기능을 쉽게 찾도록 돕는다. 사용자가 확장 버튼을 누르면 DOM을 분석하고, 실제로 발견한 핵심 기능을 최대 6개까지 쉬운 화면에 표시한다. 기존 사이트의 로그인·인증·업무 로직은 원본에서 이용한다.

## 이번 작업의 범위

- Chrome Manifest V3 확장 프로그램, TypeScript, 로컬 규칙 기반 분석.
- 실행 시점에만 `activeTab` + `scripting` 사용. 자동 실행·모든 사이트 상시 접근 권한 없음.
- 로그인·검색·공지·학사정보·신청/조회·이용 안내 분류. 미발견 기능은 만들어 표시하지 않음.
- 검증 가능한 일반 HTTP(S) 링크는 이동. 버튼·앵커·스크립트 기능은 원본 위치를 강조하고 직접 이용하게 함.
- 원본 DOM을 재작성하지 않고 Shadow DOM의 모달 화면을 추가. Esc/닫기/확장 버튼 재실행으로 복귀.
- 서버·계정·외부 AI·입력 내용 수집·분석 결과 전송·인증 및 제출 자동화는 이번 범위에 포함하지 않음.

## 단계별 작업과 완료 기준

| 단계 | 작업 | 완료 기준 | 상태 |
| --- | --- | --- | --- |
| 1 | 작업 계획·프로젝트·빌드 구성 | 계획 파일, README, 재현 가능한 빌드 명령 | 완료 |
| 2 | 확장 실행과 원본 복귀 | 실제 확장 로딩, 중복 실행 시 화면 하나, 종료 후 원본 사용 가능 | 테스트 프로필에서 확인 |
| 3 | 수집·분류·순위 모듈 | 숨김/비활성 제외, 의미 있는 기능만 표시, 동일 분류 중복 제거 | 1차 구현·테스트 완료 |
| 4 | Easy Mode와 원본 연결 | 큰 버튼, 작은 화면 배치, 키보드 조작, 이동/위치 안내 | 로컬 예시에서 확인 |
| 5 | 자동 검증·첫 사이트 점검 | 타입 검사, 기능 테스트, 상명대 공개 홈페이지 관찰 결과 기록 | 완료, 실제 업무 수행은 미확인 |
| 6 | 사용자 환경에서 수동 확인 | 사용자의 Chrome 설치 및 원본 기능 도달 확인 | 예정 |
| 7 | 구조가 다른 4개 사이트 확대 | 대학 포함 총 5개 사이트의 대상 과제·오탐·누락 기록 | 후속 |
| 8 | 사용자 비교 실험 | 성공률·시간·클릭·오클릭의 일반 화면 대비 관찰값 확보 | 후속 |

## 구현 구조

`background → content → analyzer → classifier → ranker → easy-mode → action-bridge`

- `analyzer`: 문구·접근성 이름·링크·메뉴 위치 수집. 텍스트 입력값은 읽지 않음.
- `classifier`: 분류 규칙과 근거 생성. 점수는 휴리스틱이며 정확도 확률이 아님.
- `ranker`: 분류당 한 개를 선택하여 최대 6개 표시.
- `easy-mode`: 독립 스타일, 키보드 초점, 닫기, 원본 복귀.
- `action-bridge`: 원본 요소 위치 안내. 임의 클릭·폼 제출은 하지 않음.

## 검증 방법

1. 재현 가능한 로컬 대학 예시 페이지에서 수집·분류·숨김·위험 링크·입력정보 비수집 검증.
2. Chromium에서 화면 열기/닫기, 초점, 실제 링크 이동, 원본 요소 안내, 중복 실행 검증.
3. 설치된 확장을 테스트 프로필에서 로딩하고 서비스 워커의 스크립트 주입 확인. 자동화에서는 실제 사용자 도구 모음 클릭과 권한 부여를 별도로 구분.
4. 상명대 공개 홈페이지를 읽기 전용으로 확인. 탐지 결과는 성공한 업무 수행과 구분. 로그인·인증·신청·제출은 실행하지 않음.
5. 체크 결과와 미확인 사항은 `docs/VALIDATION.md`에 기록. 테스트하지 않은 항목을 완료로 처리하지 않음.

## 후속 설계 결정

- 범용 규칙과 사이트별 보정 규칙의 성능은 분리해서 측정한다. 첫 버전은 범용 규칙으로 시작한다.
- AI 도입은 실제 누락/오탐 사례를 모은 뒤 판단한다. DOM 전체를 외부로 보내는 구조를 기본값으로 삼지 않는다.
- 현재 페이지에 없는 하위 메뉴, 교차 출처 iframe, 닫힌 Shadow DOM, 브라우저 내부 페이지는 지원 범위를 별도로 관리한다.
- 사용성 개선 가설: 일반 화면보다 과제 성공률을 유지 또는 개선하면서 탐색 시간·오클릭 감소. 아직 검증된 효과가 아니다.

## 다음 회차

먼저 사용자의 Chrome에서 첫 버전을 실행하고 상명대 홈페이지에서 선택한 기능으로 도달하는지 확인한다. 그 결과로 탐지 규칙과 화면을 보완한 뒤 지자체·정부기관·공공기관·도서관으로 확대한다.
