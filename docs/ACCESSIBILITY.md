# 접근성 검증과 수동 확인

v0.5.0 개발 후보의 자동 검사와 실제 보조기술 확인을 구분한다. 최신 수치·소스 해시는 [RUN-004 자동 검사 JSON](evidence/run004/a11y-automated.json), 최종 판정은 [진행표](PROGRESS.md)를 따른다. 정식 접근성 인증 결과가 아니다. 현재 버전의 실제 VoiceOver 발화·브라우저 확대·네이티브 설치 검사는 **NOT_RUN**이다.

## 자동·키보드 검사

`npm run test:a11y`는 합성 공개 메뉴에서 정상·빈 결과·긴 이름·원본 변경·원본 안내 성공/실패·추가 메뉴 전환을 검사한다. 1440px, 720px, 390px, 320 CSS px, 강제 색상, 모션 감소를 조합한 21가지 상태에 axe-core를 적용한다. 최종 검사에서 오류·위반·미판정은 각각 0건이다. 텍스트·경계·초점 대비, 48px 목표 영역, 가로 넘침, 접근성 이름과 실제 링크/버튼 역할, Tab/Shift+Tab 순환과 종료 후 복귀도 기록한다. `npm run verify`의 관련 회귀는 상태 안내와 안내창의 Escape·외부 제거 후 정리, 추가 메뉴의 초점·오래된 후보 차단과 숨은 이전/다음 버튼의 접근성 트리 제외를 확인한다.

메뉴 전환은 첫 카드로 초점을 옮겨 대화상자를 스크롤할 수 있다. 전체 내용의 axe·대비 스냅샷은 스크롤을 맨 위로 정규화한 뒤 수집하고, 실제 전환 시 초점·스크롤 동작은 별도 회귀로 검사한다. 첫 후보에서 상단이 잘려 생긴 대비 미판정 1건은 [이전 원본 결과](evidence/run003/verify-first-integration-failure/v0.4-first-a11y-automated.json)에 보존했다. 이 도구 보정은 실제 확대 검사를 대신하지 않는다.

이 검사는 원본 기관 사이트 전체의 접근성을 판정하지 않는다. 320 CSS px 재배치 검사는 모바일 Chrome 확장 지원을 뜻하지 않는다. 자동 검사에서 오류가 없다는 사실만으로 스크린리더 음성 안내가 맞다고 판정하지 않는다.

## 네이티브 확대·VoiceOver 기록

아래는 **v0.3 계열의 과거 예비 관찰**이며 v0.5 검증으로 승계하지 않는다. 별도 Google Chrome for Testing 프로필에 원래 Manifest를 설치해 도구 모음으로 실행한 화면에서 브라우저 확대 표시 200%, 400%와 키보드 초점을 관찰했다. 예비 설치 빌드의 관찰은 [native-ui-check.json](evidence/run002/native-ui-check.json)에 보존한다.

VoiceOver를 켜고 Chrome 카드로 초점을 옮기는 과정은 수행했다. 실제 읽힌 음성·캡션의 이름과 상태 메시지를 독립적으로 확인하지 못했으므로 **PARTIAL_UNVERIFIED_SPEECH**이며 S06 인수 통과가 아니다. 검증 뒤 VoiceOver 설정은 원래 꺼진 상태로 복원했다. Windows/NVDA 실기기는 확인하지 않았다.

## 남은 VoiceOver 수동 확인

변경·가려짐·복구 상황을 일정하게 만들 수 있는 [수동 확인실](MANUAL_CHECK.md)을 준비했다. 사람이 직접 듣고 기록하는 결과는 여전히 NOT_RUN이며, 확인실의 헤드리스 검사와 실제 음성 결과를 구분한다.

음성을 들을 수 있는 사람이 최종 후보의 버전·Chrome 버전·일시를 적고 확인한다. macOS 시스템 설정 → 손쉬운 사용 → VoiceOver에서 켜고, 기존 설정은 시험 후 복원한다. 공개 데모에서만 진행하며 개인 계정·입력은 필요 없다.

1. [수동 확인실](http://127.0.0.1:4183/manual-check.html)을 열고 도구 모음에서 EasyWeb을 실행한다. 모달의 제목·설명과 처음 초점인 `원본 화면 보기`가 맞게 읽히는지 듣는다.
2. Tab과 Shift+Tab으로 `다시 찾기`, 각 기능 카드, 복귀 버튼을 순환한다. 일반 링크는 링크, 원본 안내는 버튼으로 읽히며 이름·원본 메뉴·외부 목적지·새 창 정보가 이해 가능한지 확인한다. 추가 메뉴가 있는 별도 예시에서는 `다른 메뉴 보기`·`이전 메뉴`의 이름, 전환 후 첫 카드 초점과 상태 발화도 확인한다. 두 메뉴만 있는 수동 확인실의 성공만으로 추가 메뉴의 실제 발화를 통과 처리하지 않는다.
3. `다시 찾기`를 선택한다. 초점이 유지되고 새 탐지 개수·상태 알림이 읽히는지 듣는다. 화면 밖으로 초점이 빠지지 않는지 확인한다.
4. 원본 안내 버튼을 선택한다. 원본 제어로 초점이 이동하고 위치 안내 상태가 읽히는지 듣는다. 성공은 원본 기능 실행 완료와 다르다. 가려짐·변경 실패에서는 오류가 읽히고 안내 닫기 버튼을 찾을 수 있어야 한다.
5. Esc/복귀로 닫은 뒤 원래 제어와 스크롤 위치를 확인하고 다시 실행한다. 오래된 안내나 중복 모달이 읽히면 실패로 기록한다.

기록에는 각 항목 `PASS/FAIL/NOT_TESTED`, 실제 들린 짧은 문구, 예상과 다른 초점·재현 순서만 적는다. 합성 데이터의 접근성 트리 스냅샷으로 음성 결과를 대신 채우지 않는다. 실제 확인이 모두 통과하고 차단 결함이 없을 때만 S06을 완료로 바꾼다.
