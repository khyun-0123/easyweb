## 동작 정책

처음에는 최대 6개 메뉴를 보여주며 **다른 메뉴 보기 / 이전 메뉴**로 추가 후보를 탐색한다. 실제 본문 관계의 근거 단계를 먼저 반영하고 같은 단계에서는 분류 다양성을 확보해 최대 6개를 채우며, 최초 6개 품질 평가 기준은 유지한다.

일반 HTTP(S) 링크는 사용자의 선택에 따라 직접 이동한다. 명시적 JavaScript·팝업·같은 문서 fragment·인증·다운로드 제어는 원본 위치를 안내하고 사용자가 계속한다. 다른 문서로 가는 fragment 링크는 일반 링크처럼 직접 이동한다. 원본 안내는 초점·가시성·가림·변경 검사를 통과해야 성공 메시지를 낸다. 카드가 표시됐다는 사실은 과제 완료가 아니다.

DOM 표식 없는 property/위임 클릭 이벤트는 확장 isolated world에서 완전히 식별할 수 없다. 일반 링크 카드가 원본 JS/SPA 처리를 우회할 수 있다는 한계가 있다. 불투명한 서버 다운로드 URL과 SSO 경로도 완전하게 식별하지는 못한다. 원본 앱의 모든 행동 보존·업무 성공을 보증하지 않는다. [정의 사례와 실제 world 관찰](ACTION_POLICY.md)을 따른다.

## 환경

- macOS arm64의 Chromium 자동 검사를 사용한다. 별도 Google Chrome for Testing의 네이티브 설치 경로 관찰은 RUN-002의 v0.3.0 과거 기록이다. **현재 v0.9.0 네이티브 설치 경로는 NOT_RUN**이며 사용자 기존 Chrome 프로필은 변경하지 않았다.
- 일반 최상위 HTTP(S) 문서의 현재 보이는 DOM을 분석한다. iframe 내부·닫힌 Shadow DOM은 수집하지 않는다. 열린 Shadow DOM 내부의 재귀 수집도 현재 구현 범위가 아니다.
- Chrome 내부 페이지·웹 스토어 등 주입 제한 페이지는 오류 배지와 일반 페이지 재실행 안내를 사용한다. 제한을 우회하지 않는다.
- 320px 재배치 검사는 좁은 화면 배치 검사다. 모바일 Chrome 확장 실행·Windows Chrome·NVDA 실기기 호환 완료를 뜻하지 않는다.
- **실제 VoiceOver 발화·상태 안내, 실제 브라우저 확대, 현재 v0.9.0의 수동 복구는 미검증**이다. [수동 확인 안내](MANUAL_CHECK.md)와 <http://127.0.0.1:4183/manual-check.html>를 사용하고 실제 관찰 후 기록한다. 자동 AX·키보드·좁은 화면 검사를 실제 발화·실제 브라우저 확대 통과로 바꾸지 않는다.
- 실제 사용자 실증 관찰은 **0건 / NOT_RUN**이다. [접근성 문서](ACCESSIBILITY.md), [1인 사전 시험](PRETEST.md), [정식 실증 문서](USER_STUDY.md)의 범위를 구별한다.

## 보고할 때

공개 페이지 URL, 후보 버전, Chrome 버전, 선택한 카드의 고정 이름, 기대/실제 결과, 재현 순서를 기록한다. 로그인 정보·입력 내용·비공개 화면은 넣지 않는다. `카드 없음`, `다른 목적지`, `원본 가림`, `초점 실패`, `변경 안내`, `복귀 실패`처럼 관찰한 사건을 구분하면 재현에 도움이 된다.
