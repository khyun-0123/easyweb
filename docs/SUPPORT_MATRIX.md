고정 과제의 원본 문구·정확한 URL·공개 목적지/원본 제어 구분은 [정답 데이터](../evaluation/README.md)에 있다. 축약 fixture 수치, 실제 전체 페이지의 15개 공개 과제, 설치된 확장의 도구 모음 실행, 실제 사용자 실증을 서로 대체하지 않는다.

## 동작 정책

일반 HTTP(S) 링크는 사용자의 선택에 따라 직접 이동한다. 명시적 JavaScript·팝업·fragment·인증·다운로드 제어는 원본 위치를 안내하고 사용자가 계속한다. 원본 안내는 초점·가시성·가림·변경 검사를 통과해야 성공 메시지를 낸다. 카드가 표시됐다는 사실은 과제 완료가 아니다.

DOM 표식 없는 property/위임 클릭 이벤트는 확장 isolated world에서 완전히 식별할 수 없다. 일반 링크 카드가 원본 JS/SPA 처리를 우회할 수 있다는 한계가 있다. 불투명한 서버 다운로드 URL과 SSO 경로도 완전하게 식별하지는 못한다. 원본 앱의 모든 행동 보존·업무 성공을 보증하지 않는다. [정의 사례와 실제 world 관찰](ACTION_POLICY.md)을 따른다.

## 환경

- macOS arm64의 Chromium 자동 검사와 별도 Google Chrome for Testing 네이티브 설치 경로를 기록한다. 사용자 기존 Chrome 프로필은 변경하지 않았다.
- 일반 최상위 HTTP(S) 문서의 현재 보이는 DOM을 분석한다. iframe 내부·닫힌 Shadow DOM은 수집하지 않는다. 열린 Shadow DOM 내부의 재귀 수집도 현재 구현 범위가 아니다.
- Chrome 내부 페이지·웹 스토어 등 주입 제한 페이지는 오류 배지와 일반 페이지 재실행 안내를 사용한다. 제한을 우회하지 않는다.
- 320px 재배치 검사는 좁은 화면 배치 검사다. 모바일 Chrome 확장 실행·Windows Chrome·NVDA 실기기 호환 완료를 뜻하지 않는다.
- VoiceOver 실제 음성 이름·상태·초점 확인과 정식 사용자 실증은 각 [접근성 문서](ACCESSIBILITY.md), [실증 문서](USER_STUDY.md)의 상태를 따른다.

## 보고할 때

공개 페이지 URL, 후보 버전, Chrome 버전, 선택한 카드의 고정 이름, 기대/실제 결과, 재현 순서를 기록한다. 로그인 정보·입력 내용·비공개 화면은 넣지 않는다. `카드 없음`, `다른 목적지`, `원본 가림`, `초점 실패`, `변경 안내`, `복귀 실패`처럼 관찰한 사건을 구분하면 재현에 도움이 된다.
