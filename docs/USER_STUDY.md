# EasyWeb 공개 메뉴 도달 사용성 실증 안내

상태: **준비 완료 / 실제 실증 미실시**. 이 문서는 정식 S09의 6~8명 비교 실험 전용이다. 계획 식별자 P01~P08은 실제 참여자가 있다는 뜻이 아니다. 이 안내서·빈 기록·분석기·합성 검증만으로 S09를 DONE으로 세지 않는다. 실제 참여자 모집·연락·동의·실행·관찰·효과 판정은 아직 수행하지 않았다.

기준은 [WORK_SPEC S09](WORK_SPEC.md)이며 최신 기술 준비 상태는 [PROGRESS](PROGRESS.md)를 따른다. 정식 S09 세션은 S06~S08의 필수 접근성·원본 연결·동일 배포본 설치 검증을 확인한 뒤 시작한다. 준비 문서가 있다는 이유로 그 조건이 통과된 것은 아니다.

## 먼저 해 보는 1인 사전 시험

사용자가 먼저 확인할 수 있도록 [5~10분 사전 시험](PRETEST.md)과 `evaluation/pretest/`의 별도 빈 기록을 준비했다. 안정된 후보 빌드가 전달된 뒤 5개 사이트에서 작동·안내 이해·원본 복귀를 한 번씩 살펴보는 절차다. 원본/EasyWeb 반복 시간 비교를 하지 않으며 정량 효과 검증이 아니다. 익명 코드 `PILOT01`은 사전 배정일 뿐 실제 참여·실행을 뜻하지 않는다. 현재 사전 시험도 **NOT_RUN**이다.

사전 기록은 이 정식 실험의 6~8명·사이트별 최소 6개 짝 관찰·전체 배정·성공률·시간 감소율 분모에 넣지 않는다. 정식 분석 CLI에 사전 CSV를 입력하지 않으며 정식 `P01` 등으로 바꿔 재사용하지 않는다. 사전 시험 완료로 S09·S10을 DONE 처리하지 않는다. 같은 사람이 추후 정식 실험에 참여하려면 사전 노출에 따른 학습 효과와 새 배정을 별도 계획·기록해야 한다.

## 무엇을 비교하는가

같은 참여자가 같은 공개 메뉴 도달 과제를 원본 화면과 EasyWeb 화면에서 각각 수행한다. **성공은 정해 둔 공개 목적지 또는 원본 제어까지 도달하는 것**이다. 카드가 추천되거나 화면이 열렸다는 사실만으로 성공 처리하지 않는다. 실제 인증·개인정보 입력·검색 제출·신청·결제·삭제·파일 다운로드·프로그램 설치·민원 접수는 수행하지 않는다.

`navigate` 과제는 정답의 공개 URL과 화면에 도달했는지 확인한다. 일반 링크 카드는 직접 이동하며, JavaScript·SSO·다운로드 등 동작을 대신 실행하기 어려운 제어는 원본 위치로 안내한다. `locate` 과제는 해당 원본 제어가 보이고 초점 또는 강조 대상이 맞는지 확인한 뒤 멈춘다. FAQ 펼침·국민신문고 버튼·다운로드 링크 등을 대신 실행하지 않는다. 공개 목적지 도달 과제가 원본 제어 안내까지만 끝났다면 목적지 도달 성공으로 바꾸지 않는다. 종료 후 원본으로 돌아갈 수 있는지는 별도 항목으로 기록한다.

15개 과제는 현재 [sites 정답표](../evaluation/sites/)에서 가져와 [과제 카드](../evaluation/study/tasks.md)와 [plan.json](../evaluation/study/plan.json)에 고정했다. 과제·시작 URL·원본 정답 파일 SHA256을 보관한다. 실제 사이트에는 평가용 `data-eval-id`가 없으므로 진행자는 실제 문구·목적지·원본 제어로 판단한다. 원본 사이트가 바뀌거나 접근이 막히면 `blocked`와 근거를 기록한다. 결과를 본 뒤 불리한 과제를 빼거나 같은 자료의 정답을 조정하지 않는다.

## 참여자와 배정

대상은 복잡한 웹사이트에서 메뉴를 찾는 데 어려움을 느끼거나 큰 글씨·간단한 안내를 원하는 동의 가능한 성인 6~8명이다. 진단명·이름·연락처·계정·정확한 생년월일은 결과표에 받지 않는다. 모집과 동의는 이후 진행자가 별도로 수행하며, 이 작업에서는 누구에게도 연락하지 않았다. 동의 여부와 대상 적합성은 진행자가 확인하고 익명 코드로만 체크한다. 언제든 이유 없이 중단할 수 있다.

참여자 수를 수집 전에 6·7·8명 중 하나로 고정한다. 선택한 배정의 모든 과제를 분모에 남긴다. 결과가 나쁜 참여자를 사후 제외하거나 8명 계획을 성과에 따라 6명 계획으로 줄이지 않는다.

| 계획 | 참여자당 과제 | 총 짝 | 총 시행 | 사이트별 짝 | 15개 과제별 짝 |
| --- | --- | --- | --- | --- | --- |
| [6명](../evaluation/study/assignments-6.csv) | 사이트별 1개, 총 5개를 양쪽 조건에서 수행 | 30 | 60 | 6 | 각 2 |
| [7명](../evaluation/study/assignments-7.csv) | 동일 | 35 | 70 | 7 | 각 2~3 |
| [8명](../evaluation/study/assignments-8.csv) | 동일 | 40 | 80 | 8 | 각 2~3 |

각 참여자의 사이트 순서는 회전 배정한다. 각 과제 쌍의 조건 순서는 원본 먼저/EasyWeb 먼저를 교차 배정한다. 6명·8명 계획은 사이트마다 두 순서가 동수이며, 7명 계획은 차이가 1개다. 참여자는 5개 블록, 블록당 두 번을 수행한다. 연습은 연구에 포함하지 않는 별도 로컬 예시에서 한 번만 한다. 연습 자료·연습 시간은 두 조건에 같은 기준으로 적용한다.

같은 과제를 두 번 보는 학습 효과는 완전히 없어지지 않는다. 각 시행 사이 최소 1분 쉬고 시작 페이지·스크롤·초점·탭 상태를 초기화한다. 정답 위치를 알려 주지 않으며 조건 순서별 결과도 별도 보고한다. 두 블록마다 추가 휴식을 권한다. 참여자가 지치면 중단하고 남은 배정을 미관찰로 남긴다.

## 진행자가 읽을 문장

“이 테스트는 공개 웹사이트의 메뉴를 찾는 방법을 비교합니다. 당신의 능력을 평가하는 시험은 아닙니다. 계정·검색어·개인정보는 입력하지 않습니다. 신청이나 다운로드는 하지 않습니다. 불편하면 언제든 멈추거나 도움을 요청할 수 있습니다. 이름 대신 익명 번호로 기록합니다. 실제 화면 기록이 필요하면 별도로 동의를 받은 공개 영역만 남기겠습니다.”

동의 확인 후 과제 카드의 시작 URL과 참여자 문장만 읽어 준다. 진행자용 정답·추천 카드 이름·메뉴 위치는 먼저 보여 주지 않는다. 자동화로 사람의 반응·동의·도움 요청을 만들어 넣지 않는다.

## 시행 순서와 시간

1. 설치에 사용한 ZIP/빌드 해시·버전, OS·Chrome 버전, 화면 크기·확대율·입력 방식·보조기술, 사이트 URL과 수집 날짜를 기록한다. 익명 코드만 사용한다.
2. [선택한 배정표](../evaluation/study/)의 `trial_order` 순서로 시작 페이지를 불러온다. 이전 조건의 EasyWeb UI는 닫고 탭·스크롤·초점을 초기화한다. 시작 페이지 로딩 자체가 불가능하면 `blocked`로 기록한다.
3. 과제 문장을 읽고 참여자가 준비됐다고 말한 뒤 타이머를 시작한다. 원본 조건은 원본 화면에서, EasyWeb 조건은 **도구 모음 실행부터** 시작한다. 확장 주입·화면 준비 시간을 EasyWeb 조건에서 빼지 않는다.
4. 정답의 공개 목적지 또는 원본 제어가 확인되는 순간 타이머를 멈춘다. 목표 페이지 로딩은 실제 도달 시간에 포함한다. 제한은 시행당 **180,000ms(180초)**다. 제한이 되면 `timeout`, 시간은 180,000ms로 기록한다. 성공 시간은 0보다 크고 제한 이하여야 한다.
5. 실패·차단·중단도 경과 시간·오클릭·도움 요청·잘못된 안내를 기록한다. 시작 전 중단·차단은 0ms일 수 있다. 실행하지 않은 배정은 행을 만들지 않거나 `not_run`과 빈 측정값으로 남긴다. 관찰하지 않은 수치를 0으로 채우지 않는다.
6. EasyWeb 조건에서는 주 과제 시간 측정 후 별도로 원본 복귀를 시도하게 하고 `yes/no/not_attempted`로 기록한다. 이 복귀 시도 시간은 주 과제 시간에 합치지 않는다. 원본 조건은 `not_applicable`이다.
7. 각 시행 뒤 난이도를 1(매우 쉬움)~5(매우 어려움)로 묻는다. 대답을 원하지 않으면 빈칸으로 둔다. 세션 뒤 [사후 설문](../evaluation/study/post-survey.blank.csv)을 진행한다.

안전 경계를 벗어날 조짐이 보이면 즉시 멈춘다. 심각한 잘못된 안내와 의도하지 않은 인증·제출·결제·삭제·다운로드 등은 각각 해당 플래그와 사건 근거를 남긴다. 카드 추천 수나 탐지 성공을 사용자의 실제 성공으로 바꾸지 않는다.

## 기록 양식

[observations.blank.csv](../evaluation/study/observations.blank.csv)는 헤더만 있는 실제 관찰용 빈 파일이다. 원본을 복사해 수집본을 만든다. [완료 판정 빈 기록](../evaluation/study/completion-record.blank.json)은 독립적인 검토용이며 모든 실제 확인 값이 비어 있다. 빈칸은 미확인이지 0건·통과가 아니다.

| 필드 | 기록 규칙 |
| --- | --- |
| `data_kind` | 실제 관찰은 `real`. 합성 검증은 `synthetic`이며 실제 자료와 섞지 않는다. |
| `participant_id`, `task_id`, `condition`, `trial_order` | 배정표 그대로. 조건은 `original/easyweb`. 같은 참여자·과제·조건 중복은 거부한다. |
| `outcome` | `success/failure/timeout/blocked/withdrawn/not_run`. 실패·차단·중단을 성공으로 재분류하지 않는다. |
| `elapsed_ms` | 실제 경과 ms. 성공은 >0, 모든 시행은 ≤180000. timeout은 180000. |
| `misclicks`, `help_requests` | 관찰한 정수 횟수. 도움은 먼저 답을 주는 대신 요청 사실과 제공 수준을 코드로 남긴다. |
| `returned_to_original` | 원본: `not_applicable`. EasyWeb: `yes/no/not_attempted`. 성공한 EasyWeb 시행은 별도 복귀 시도 결과가 필요하다. |
| `difficulty` | 1~5, 응답 거절은 빈칸. |
| `serious_wrong_guidance`, `unexpected_sensitive_action` | 관찰 후 0 또는 1. 관찰하지 않은 행에서 0으로 만들지 않는다. |
| `evidence_ref` | 공개 화면·익명 관찰 메모의 로컬 경로/기록 코드. 실제 관찰행은 필수. 참고 문자열만 있다는 사실은 검증 완료 증거가 아니다. |
| `observer_note` | `site_unavailable`, `no_candidate`, `wrong_control`, `obscured`, `participant_stopped` 등 사건 코드. 실제 입력값·이름·계정·화면의 사적 내용을 쓰지 않는다. |

`not_run`은 측정값·근거·메모를 모두 빈칸으로 둔다. 이미 수행한 시행을 재시도했으면 기존 행을 덮어쓰지 말고 별도 프로토콜 변경 기록을 만들고 분석 범위를 검토한다. 이 버전은 참여자·과제·조건당 사전 배정 1회만 분석한다.

사후 설문은 두 조건 난이도(각 1~5), EasyWeb 안내 신뢰(1~5), 선호 조건(`original/easyweb/same/decline`), 다시 사용할 의향(`yes/no/unsure/decline`)을 묻는다. 도움이 된 점은 `large_text/shortcuts/focus/none/other`, 문제는 `missing_feature/wrong_guidance/return_problem/reading/none/other` 코드로 기록한다. 자유 발언을 남길 때도 개인 정보나 입력 내용 대신 익명화한 사건 코드만 결과 파일에 옮긴다. 사후 설문은 진행자가 별도 검토하며 분석 CLI의 시행 지표와 혼동하지 않는다.

## 분석 명령과 사전 지표

저장소 루트에서 실행한다. 실제 수집 파일은 별도 이름으로 보관하고 빈 원본을 덮어쓰지 않는다.

```bash
# 빈 양식: NOT_RUN, 관찰 0, 인수 NOT_EVALUATED가 나와야 한다.
node scripts/analyze-study.mjs

# 실제 수집본: 계획 인원은 수집 전에 고정한 값을 쓴다.
node scripts/analyze-study.mjs --input=evaluation/study/observations.real.csv --participants=6 --out=evaluation/study/analysis.real.json

# 분석기만 검사하는 합성 단위검증. 실제 참여자 결과가 아니다.
node --test evaluation/study/analyze-study.test.mjs
```

CLI는 원본 입력과 plan의 SHA256, 전체 배정·미관찰·성공·실패·차단·중단·도움·오클릭·복귀·난이도, 사이트·과제·조건 순서별 표를 출력한다. 합성 CSV를 별도로 시험하려면 `--allow-synthetic`을 명시해야 하며 출력은 `SYNTHETIC_ONLY`다. 빈 자료·합성 자료는 실제 제품 인수 PASS가 될 수 없다.

- 사이트당 6개 짝 관찰의 충족에는 양쪽 조건을 실제 시도한 쌍(success/failure/timeout)을 센다. blocked/withdrawn 기록은 전체 분모와 결과표에 남지만 실제 짝 관찰을 대신하지 않는다.
- 성공률 분모는 선택한 계획의 전체 배정 쌍이다. 두 조건에 같은 분모를 사용한다. 실패·timeout·blocked·withdrawn을 남기며, 미관찰 배정도 빠진 수를 보인다. 자료가 불완전할 때 성공/전체배정 비율은 관찰된 성공의 하한이며 효과 비교·완료 판정을 내리지 않는다.
- 시간 주지표는 **양쪽 성공한 동일 참여자·동일 과제 쌍의 동일 집합**에서 `1 − median(EasyWeb 시간) / median(원본 시간)`이다. 목표는 20% 이상 감소다. 그 집합의 각 쌍 감소율 중앙값도 보조로 제시하되 주지표로 대체하지 않는다. 양쪽 성공 쌍이 없으면 시간 효과는 N/A이며 통과가 아니다.
- 시간 집합에서 빠진 실패·차단·미관찰 쌍의 개수와 양 조건 결과를 함께 보고한다. 원본만 성공/EasyWeb만 성공/둘 다 실패/쌍 불완전도 분리한다. 원본 조건과 EasyWeb 조건에서 서로 다른 성공 표본을 독립적으로 골라 중앙값을 비교하지 않는다.
- 제품 목표는 심각한 잘못된 안내 0건, 의도하지 않은 민감 동작 0건, 전체 배정 쌍에서 성공률 유지/개선, 위 시간 목표다. 실제 자료가 모두 기록되어도 CLI는 `PENDING_MANUAL_EVIDENCE_REVIEW`만 출력한다. 대상 적합성·동의·근거·프로토콜을 사람이 확인해야 한다.

작은 표본의 탐색적 비교다. 통계적 일반화·인과 효과 확정·접근성 인증으로 표현하지 않는다. 조건 순서별 차이가 크면 학습 효과와 프로토콜 영향을 함께 보고한다.
