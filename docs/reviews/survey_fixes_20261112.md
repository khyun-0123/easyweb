# 사이트 조사 재생으로 고친 카드 선택 문제

EasyWeb · 2026-11-12 · v0.11 작업 중

## 한 줄 결론

- 2026-11-01 사이트 조사에서 저장한 화면 134쪽에서, 잘못 고른 카드와 놓친 필수 기능을 다시 분류했습니다. 여러 사이트에 공통으로 나타나고 좁게 고칠 수 있는 7가지를 고쳤습니다.
- 같은 134쪽, 같은 검토 기준에서 **첫 화면 필수 기능 포함 37.2% → 41.3%**, **쓸모 있는 카드 55.4% → 59.4%** 로 올랐습니다.
- 기존 검사(전체 539개, core, 60페이지 두 모드)는 수정 전과 같거나 통과입니다.
- 이 숫자는 모두 **개발에 이미 쓴 자료**에서 나왔습니다. 처음 보는 자료에서 나아졌다는 증거는 아닙니다.

## 1. 무엇을 봤나

- 자료: `evidence/run010/site-survey-20261101b`의 저장 화면 136쪽과 엔진을 보지 않은 검토 134쪽(검토 기준은 [사이트 조사 보고서](site_survey_20261101.md) 1절)
- 조사 도구가 카드마다 `context`(primary/body/footer)·점수·근거 첫 줄을 함께 남기도록 넓혔습니다(`scripts/site-survey.mjs`).
- 잘못 고른 카드 290개 가운데 약 136개(47%)는 같은 사이트의 여러 페이지에 반복되는 공통 메뉴였습니다. 다만 엔진은 한 페이지만 보므로 이 정보를 직접 쓸 수 없습니다. 영역(primary/body)만으로는 잘 나뉘지 않았습니다. 내부 페이지 primary 카드의 쓸모 51%, body 카드는 58%였습니다. 그래서 이번에는 공통 메뉴 전체를 낮추는 규칙은 만들지 않았습니다.

**고치는 중 생긴 회귀와 처리**

- 6번 규칙을 처음 넣었을 때 기존 테스트 1개가 실패했습니다. 이 테스트는 「청사 안내」 같은 안내 이름이 본문 우선 기능이 되지 않아야 한다는 기존 설계를 지킵니다. → 안내 이름은 분류만 하도록 규칙을 둘로 나눴습니다.
- 그 상태로 60페이지 비교를 돌리자 천안시 홈 fixture에서 정답표의 「통합검색」이 6칸 밖으로 밀렸습니다. 범용 모드 재현율도 145 → 144/170(0.847)이 되어 기준 0.85 아래인 **FAIL**이 났습니다. 원인은 「찾아오시는 길」과 「무료상담운영」이 둘 다 우선 칸을 차지한 것입니다. [10 페이지 유형](../10_page_types.md) A는 홈에서 둘을 한 칸으로 정해 두었습니다. → 홈에서는 위치 안내가 우선 칸을 차지하지 않게 고쳤고, 145/170 PASS로 돌아왔습니다. 이 FAIL 실행(전체 539/539지만 core 44/45, 60페이지 범용 FAIL)은 `survey-fixes-verify`·`survey-fixes-development-comparison`에 그대로 남겼습니다. **앞의 테스트 1개 실패 실행(536/537)은 같은 폴더를 다시 쓰면서 지워져 기록이 없습니다.** 그 전에 소스를 고치는 도중이라 멈춘 실행 1개는 결과가 섞였을 수 있어 증거에서 빼 두었습니다(`tmp/aborted-survey-fixes-verify`, 저장소 밖).

## 4. 아직 남은 것

- **공통 메뉴 반복**: 잘못 고른 카드의 절반쯤입니다. 한 페이지 안에서 공통 메뉴를 알아볼 신호(사이드 메뉴의 현재 위치, 머리 메뉴 구조)를 더 찾아야 합니다.
- **놓친 필수 기능의 대부분은 여전히 후보가 아님**: 조직도 하위 목록, 하단에만 있는 「찾아오시는 길」(4쪽), 홈의 묶음 제목이 없는 대표 서비스.
- **서비스 안내(32%)·안내 문서(32%)·일정(25%)**: 이번에 손대지 않았습니다.
- 처음 보는 자료 평가와 사람 확인은 0건입니다.
