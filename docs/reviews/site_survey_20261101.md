# 사이트 조사 보고서 — 페이지별로 어떤 기능을 몇 칸에 담을까

EasyWeb · 2026-11-01 · v0.11 작업 중

## 한 줄 결론

- **칸 수는 문제가 아니었습니다.** 지금 엔진이 놓친 필수 기능의 83%는 엔진이 아예 후보로 잡지 못한 것이었습니다. 칸을 12개로 늘려도 32%밖에 못 찾습니다.
- **필요한 칸 수는 페이지 유형마다 다릅니다.** 홈·게시판·FAQ는 6칸이 적당하고, 오시는 길·서비스 안내는 5칸, 게시글·안내 문서·일정은 4칸이면 충분했습니다. 최대 6칸 정책은 유지하고, 게시글 페이지는 4칸으로 줄였습니다.
- **채울 기능도 유형마다 다릅니다.** 게시판은 "검색 + 최신 글", 게시글은 "첨부·목록·이전/다음 글", 관문 페이지는 "사이트 고르기"였습니다. 대표 전화번호는 페이지 둘 중 하나(67/134)에서 필수로 꼽혔습니다.
- 이 결과로 **페이지 유형 판단**(게시판·게시글·관문)과 **대표 전화를 「자주 쓰는 버튼」 줄에 넣는 것**을 구현했습니다. 같은 134페이지에서 첫 화면 필수 기능 포함률 **23.9% → 37.2%**, 쓸모 있는 카드 비율 **45% → 55.3%**.
- 홈(31%)·오시는 길(22%)·서비스 안내(32%)는 아직 낮습니다. 다음 작업은 이 세 유형입니다 (아래 7절).

## 2. 몇 칸이 적절한가

검토자가 고른 "알맞은 칸 수"와 "꼭 필요한 기능 수"(중앙값):

| 페이지 유형 | 페이지 | 알맞은 칸 수 (범위) | 꼭 필요한 기능 수 | 칸을 늘렸을 때 엔진 포함률 4칸→6칸→8칸→12칸 |
| :---- | ----: | :---- | ----: | :---- |
| 게시판 목록 | 24 | **6** (5~6) | 6 | 44% → 53% → 60% → 65% |
| 홈 | 23 | **6** (4~6) | 6 | 29% → 31% → 34% → 36% |
| 오시는 길·조직·전화 | 21 | **5** (3~6) | 5 | 21% → 22% → 23% → 26% |
| FAQ | 16 | **6** (2~6) | 6 | 27% → 35% → 43% → 52% |
| 게시글 보기 | 14 | **4** (3~5) | 4 | 60% → 62% → 64% → 66% |
| 서비스·민원 안내 | 13 | **5** (3~6) | 5 | 26% → 32% → 35% → 39% |
| 안내 문서 | 13 | **4** (2~6) | 4 | 28% → 30% → 30% → 36% |
| 일정·달력 | 4 | **4** (3~5) | 4 | 25% → 25% → 25% → 31% |
| 관문(사이트 고르기) | 3 | **6** (5~6) | 6 | 29% → 35% → 35% → 35% |
| 검색 화면 | 2 | 3 (2~4) | 2 | |
| 입력 화면 | 1 | 4 | 5 | |

(포함률은 개선 후 엔진 기준)

**판단**

- 어느 유형도 6칸보다 많이 필요하다고 하지 않았습니다. **최대 6칸은 그대로 둡니다.**
- 칸을 8~12개로 늘리면 포함률이 조금 오르지만(게시판 53→65%), 대부분은 칸이 아니라 **후보를 못 찾는 문제**입니다. 칸을 늘리면 글씨·버튼이 작아지는 대가가 더 큽니다.
- **게시글 페이지는 4칸이 알맞습니다.** 6칸을 채우면 나머지 2칸은 사이트 공통 메뉴(공지사항·조직도 등)가 들어가 쓸모가 없었습니다. → 게시글 페이지는 4칸으로 구현.
- 안내 문서·일정도 4칸이 적당하지만, 아직 그 유형을 판단하는 기능이 없어 이번에는 바꾸지 않았습니다.
- 주의: 검토 기준 예시에 "6"을 적어 두어서 검토자가 6에 끌렸을 수 있습니다. 6보다 적게 고른 유형(게시글·안내 문서 4)은 그럼에도 적게 고른 것이라 더 믿을 만합니다.

**넣지 말아야 할 것 (엔진이 넣고 있던 것)**

- 엔진 카드 655장 중 쓸모 있는 것은 45%였습니다. 나머지는 주로 **내부 페이지에서 반복되는 사이트 공통 메뉴**(공지사항·조직도·부서안내·이용안내·통합검색 버튼 여러 개), 바닥글 정책 링크(웹접근성안내 등), 홍보 이벤트였습니다.
- 로그인은 홈에서도 23개 중 2개에서만 꼭 필요하다고 했습니다. 「자주 쓰는 버튼」 줄로 뺀 결정(D13)과 맞습니다.

### 게시판의 고정 공지

검토한 게시판 24개 중 21개가 "고정 공지를 카드로 따로 넣지 말 것"이었습니다. 이유:

- 대부분(18개) 고정 공지 표시가 없었습니다.
- 있는 곳(방송대·근로복지·연세대)은 같은 글이 아래 일반 목록에 다시 나왔습니다. 연세대는 고정 공지 10개가 첫 화면을 다 차지했습니다.
- 넣자는 3개는 "사기 주의"처럼 고령 사용자 피해 예방 글이 고정된 경우였습니다.

→ **번호 글을 원본 순서대로 먼저, 고정 공지는 그 뒤(「다른 기능 보기」), 같은 제목은 한 번만.**

## 4. 엔진이 놓친 이유

필수 기능 683개 중 엔진 첫 화면에 나온 것은 163개(23.9%)였습니다. 놓친 520개:

| 이유 | 개수 |
| :---- | ----: |
| 엔진이 후보로 아예 분류하지 않음 (6개 분류 어디에도 안 맞음) | **432 (83%)** |
| 후보였지만 6칸 밖으로 밀림 | 88 (17%) |

놓친 기능 종류: 게시글 80 · 대표 업무 76 · 상담·전화 72 · 오시는 길·조직 70 · FAQ 46 · 안내 32 · 첨부 26 · 같은 메뉴 관련 페이지 21 · 사이트 고르기 17 · 목록으로 14 · 이전·다음 글 9.

엔진은 "로그인·검색·공지·학사·신청조회·이용안내" 이름 근거가 있는 것만 후보로 삼습니다. 그래서 **글 제목, 전화번호(`tel:`), "목록", "이전글", "○○ 바로가기"** 같은 것은 처음부터 버려졌습니다. 칸 배치를 고쳐도 해결되지 않는 문제였습니다.
