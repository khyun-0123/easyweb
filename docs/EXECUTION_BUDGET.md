# EasyWeb 실행 시간·토큰 예산

작성일: 2026-10-17 (한국 시간)

## 해석과 한계

아래 값은 **현재 v0.1에서 5개 사이트 대상 파일럿까지 개발할 때의 실측 전 계획 추정**이다. 이미 소비한 토큰의 집계도 아니며, 모델의 실제 처리 속도·완료 시간·계정 사용량을 보장하지 않는다. 최초 1~2회 실행 후 실제 단계 소요 시간과 제공되는 사용량 계측으로 다시 산정한다.

시간은 도구 실행·디버깅·검증·문서 갱신을 포함한 에이전트 작업의 예상 경과 시간이다. 사용자 모집·사용자 응답 대기·스토어 심사·새 환경 확보 대기는 제외한다. 병렬 작업에 따라 짧아질 수 있고, 외부 사이트 변경과 디버깅으로 길어질 수 있다.

**계획상 생성 작업 토큰**은 코드·테스트·설명·추론에 사용할 작업량 예산을 뜻한다. 입력 문맥을 매 요청마다 다시 처리한 누적 토큰, 캐시 사용량, 계정별 과금 사용량과 동일하지 않다. 추론 토큰의 실제 구분·집계가 노출되지 않으면 해당 실측값도 UNKNOWN으로 기록한다. 고정된 토큰/시간 환산율은 사용하지 않는다.

## 단계별 추정

단계 범위·완료 기준은 [작업명세서](WORK_SPEC.md)를 따른다. 아래는 전체 최초 계획으로, 완료된 S01까지 포함한다. 이미 완료한 작업을 다음 실행 예산에 다시 더하지 않는다.

| 단계 | 작업 | 예상 경과 시간 | 생성 작업 토큰 추정 |
| --- | --- | --- | --- |
| S01 | 기준선·명세·진행표·병렬 검토 | 0.5~1시간 | 10,000~20,000 |
| S02 | 5개 사이트 정답 데이터 | 1~2시간 | 6,000~12,000 |
| S03 | 입력 보호·DOM 분석·변화 처리 | 2~4시간 | 12,000~24,000 |
| S04 | 분류·순위·중복 개선 | 1.5~3시간 | 10,000~20,000 |
| S05 | 원본 액션·복귀 | 2~4시간 | 12,000~24,000 |
| S06 | UI·접근성 | 2~4시간 | 10,000~20,000 |
| S07 | 사이트 회귀·성능 | 2~4시간 | 12,000~24,000 |
| S08 | 동일 배포본 설치 검증 | 1~2시간 | 6,000~12,000 |
| S09 | 실증 설계·결과 정리 | 0.5~1.5시간 | 4,000~8,000 |
| S10 | 수정·패키지·인계 | 1~2시간 | 6,000~12,000 |
| 합계 | 대기 제외, 최초 전체 계획 | **13.5~27.5시간** | **88,000~176,000** |

수정·통합·재검토용 예비분 25%를 적용하면 **약 17~35시간, 생성 작업 토큰 약 11만~22만**이 계획 범위다. 이 숫자는 코드 규모·알려진 결함·15개 페이지 검증·설치/접근성 점검을 작업 묶음으로 나눈 추정이며, 4시간에 모든 단계를 완료할 수 있다는 뜻이 아니다. 추정 오차는 크며 초기 실측 없이 정밀한 견적으로 취급하지 않는다. 단계별 예산에는 주 작업자와 필요한 하위 검토자의 생성 작업량을 포함하며, 같은 검토를 무제한 반복하지 않는다.

현재 S01 완료를 제외한 잔여 기본 추정은 **13~26.5시간, 78,000~156,000 생성 작업 토큰**이다. S09의 실제 참여자 실험은 별도 일정이 필요하다.

## 추천하는 첫 4시간 묶음

우선 목표: **입력 보호 결함 제거, 비교 가능한 정답 기준선 확보, 분석·분류의 첫 개선**. S02~S04 전체 완료를 보장하는 묶음은 아니다.

| 예상 구간 | 작업 | 종료 시 남길 결과 |
| --- | --- | --- |
| 0~15분 | 기준선·진행표 확인, 이번 묶음 범위 고정 | 선택한 하위 작업과 검증 목록 |
| 15~65분 | S03.1 contenteditable 등 입력 보호 수정 | 실패 재현 → 수정 → 비수집 회귀 증거 |
| 65~135분 | S02 사이트·페이지·정답표 구성 | 우선 확인된 사이트/페이지, 미확인 목록, 수정 전 결과 |
| 135~205분 | S03 나머지·S04의 독립적인 개선 | 의미 기반 검색창, 낡은 후보/분류·중복의 우선 개선 |
| 205~240분 | 관련 회귀·빌드·결과 정리 | 통과/실패, 수정 파일, 단계별 상태, 다음 시작 지점 |

권장 생성 작업 토큰 예산: **기본 25,000~50,000 + 예비 25% → 약 31,000~63,000**. 실행 요청용 시작값은 **50,000**, 계획상 최대치는 **65,000** 정도로 잡고 첫 실행 후 조정한다. 이는 예산 제안이며, 이번 문서 작성이 실제 4시간 실행이나 50,000 토큰 사용을 시작했다는 뜻은 아니다.

특정 하위 작업이 예상보다 커지면 205분 시점 이후 새 기능 확대를 줄이고 재현 상태·검증·재개 기록을 남긴다. 시간이 빨리 끝나도 대기하거나 불필요한 일을 추가해 4시간을 채우지 않는다. 실제 시간/토큰 상한을 사용자가 지정한 실행에서는 그 상한을 우선한다.

## 청구 토큰·비용은 별도로 계산

OpenAI 공식 안내는 입력·캐시 입력·출력에 서로 다른 요율을 사용하고, 포함 사용 한도는 계정 사용량 화면을 확인하도록 설명한다. 따라서 생성 작업 토큰 50,000을 계정의 전체 소비 토큰 50,000이나 고정 금액으로 환산하지 않는다. [OpenAI 공식 가격 안내](https://learn.chatgpt.com/docs/pricing#token-rates)

실제 사용량을 확인할 수 있는 경우 아래 항목을 실행 전후로 비교한다.

| 항목 | 기록 방법 |
| --- | --- |
| 경과 시간 | 작업 시작/종료 시각 차이와 대기 시간 구분 |
| 누적 입력·캐시 입력·출력 | 제공되는 실제 사용량 계측에서 기록. 캐시 포함 관계를 확인하여 이중 합산 금지 |
| 추론 토큰 | 제공되는 경우만 별도 기록. 출력 합계에 이미 포함되어 있으면 다시 더하지 않음 |
| 하위 에이전트 | 소비량 계측에 포함되는 범위를 확인하고 주 에이전트와 중복 합산하지 않음 |
| 단계 비용 | 해당 계정·모델·속도 설정의 실제 요율로 산정 |

비용 예측식의 일반 형태는 `(비캐시 입력 × 입력 요율 + 캐시 입력 × 캐시 요율 + 출력 × 출력 요율) / 1,000,000`이다. 실제 요율·캐시 구분·속도 설정·포함 사용량·추론 포함 관계가 확인되어야 사용할 수 있다. 이 세션에서는 계정 사용량 대시보드를 조회하지 않았으므로 실제 소비량·금액은 **UNKNOWN**이다.

모델을 읽기/단순 수정/난도 높은 디버깅에 따라 바꾸는 최적화는 사용자의 모델 선택과 사용 환경을 확인한 뒤 적용할 수 있다. 이 계획은 임의 모델 변경이나 유료 API 호출을 요구하지 않는다.

## 매 실행 종료 시 기록 양식

RUN-001은 S02~S04와 관련 액션 방어·검증을 병렬 작업으로 완료했다. 시작/종료 시각과 실제 경과는 [진행표](PROGRESS.md), 산출물과 한계는 [결과 보고서](RUN_001_REPORT.md)에 기록한다. 네 시간을 채우기 위해 범위를 추가하지 않았다. 토큰 계측이 없어 계획 대비 사용량·청구 비용은 산정할 수 없다. 한 번의 병렬 실행만으로 나머지 단계의 시간 추정을 일괄 축소하지 않는다.

```text
실행 ID / 날짜:
이번 범위:
시작 상태 → 종료 상태:
완료 조건과 증거:
관련 테스트 / 빌드:
실제 경과 시간: 값 또는 UNKNOWN
실제 입력 / 캐시 입력 / 출력 / 추론: 계측값 또는 UNKNOWN
예산 대비 관찰: 실제 계측이 없으면 추정이라고 표시
실패·미확인·사용자 참여 필요:
다음 실행 첫 작업:
```
