# 학술대회 포스터 제작 가이드 (HTML → A0 인쇄 PDF)

BarSense 2026 SMIRP 포스터를 만든 방식을 정리한 문서다. 다른 주제의 포스터를 같은 품질로 만들 때 이 순서와 규칙을 따른다.

- **완성본 (템플릿으로 그대로 복사해 쓸 수 있음):** `~/barsense/output/html/BarSense-research/poster.html`
- **결과 PDF:** `~/barsense/output/pdf/research/BarSense_Research_Poster_A0_예비측정.pdf`
- **그래프 생성 코드 예시:** `~/barsense/analysis/2026-11-19_grip_pilot/charts.py`

---

## 1. 결과물 형태

- HTML 파일 한 개(CSS 내장, 그래프는 인라인 SVG) + `assets/` 폴더의 이미지.
- 헤드리스 Chrome으로 **A0 세로(841×1189 mm) 한 장 PDF**를 뽑아 제출한다.
- 같은 HTML을 Artifact로 올려 미리보기 링크로 공유한다(사용자가 원할 때).

## 2. 페이지 구조와 크기

```css
@page { size: 841mm 1189mm; margin: 0; }
.sheet { width: 3613px; height: 5107px; zoom: 0.88; display: flex; flex-direction: column; overflow: hidden; }
.pad { padding-left: 140px; padding-right: 140px; }
```

- A0는 96 dpi에서 3179×4494 px다. 설계는 3613×5107 px로 하고 `zoom: 0.88`로 줄인다. 이렇게 하면 글자 크기를 큰 숫자로 다룰 수 있다(본문 31–34px, 섹션 제목 64px, 큰 제목 120px).
- 화면 미리보기에서는 JS로 창 너비에 맞춰 `transform: scale()`을 건다. 인쇄할 때는 `beforeprint`에서 해제한다.
- **높이가 넘치면 아래가 잘린다**(`overflow: hidden`). 그래서 수정할 때마다 반드시 측정한다(5절).

### 세로 배치 (위에서 아래로)

| 블록 | 내용 |
|---|---|
| 헤더 | 워드마크, 학회명, 제목 2줄(둘째 줄 강조색), 한 줄 소개, 저자 + 개요 칩, 오른쪽에 대표 이미지 |
| 연구 질문 띠 | 왼쪽 연구 질문(큰 글씨), 오른쪽 4칸 흐름: **왜? → 무엇을? → 결과 → 그래서** |
| 3열 본문 | 번호 섹션 01–06 (방법 → 결과 → 원인) |
| 전체 폭 섹션 | 07 정리 표 (문제 → 개선 방향) |
| 결론 상자 | 결론 문장 + 근거 카드 3장(본문 섹션 번호 표기) / 다음 실험 · 한계 · 관찰 · 참고문헌 |

## 3. 내용 원칙 (가장 중요)

사용자에게 받은 피드백에서 나온 규칙이다.

1. **설명 없이 포스터만 봐도 이해되게 쓴다.** 처음 보는 사람 기준으로 "무엇을 증명하려고, 무엇을 했고, 무엇이 나왔고, 그래서 어떤 의미인지"가 바로 보여야 한다. 연구 질문 띠의 4칸 흐름이 이 역할을 한다.
2. **쉬운 말로 쓴다.** 수식 기호(|θ|), 내부 용어(재현 14/16, 상보 필터, 백필), Q1·Q2 같은 약어를 쓰지 않는다. 꼭 필요한 개념은 한 줄 정의를 붙인다(예: "장착 보정은 센서가 붙은 방향을 앱에 알려 주는 단계").
3. **연구 질문은 데이터가 실제로 답할 수 있는 것으로 정한다.** 결과가 "모름"이 되는 질문을 세우지 않는다. 결과가 부정적이면 "차이가 없다"가 아니라 "구분되지 않았다 + 그 이유"로 쓴다.
4. **결론의 근거를 눈에 보이게 한다.** 결론 문장 바로 아래에 큰 숫자 카드 3장을 두고, 각 카드에 근거가 나온 본문 섹션 번호를 적는다(예: "근거 1 · 03").
5. **포스터만으로 완결되게 한다.** 현장 추가 자료가 있더라도, 포스터에는 "한계"와 "다음 실험"으로 빈칸을 밝혀 두고 추가 자료는 그 빈칸을 채우는 용도로 둔다.
6. **확인되지 않은 숫자는 넣지 않는다.** 기록끼리 어긋나는 값(예: 앱 반복 수와 실제 수행 횟수)은 빼거나 출처를 명시한다.
7. **실험에 쓴 실물 사진과 개념 렌더를 구분한다.** 헤더에는 목표 디자인 렌더를 둬도 되지만, "방법" 섹션에는 실제 시제품 사진을 쓰고 캡션으로 구분한다.

## 4. 디자인 규칙

### 인쇄용 흰 테마
포스터는 화면이 아니라 **인쇄물**이다. 어두운 배경은 쓰지 않는다. 프린터가 가장자리를 칠하지 못하므로, **색 상자는 종이 끝에 닿지 않게 안쪽으로 들인다**(좌우·아래 84px 여백, 둥근 모서리).

```css
:root {
  --paper: #ffffff; --ink: #0e1622; --ink-soft: #364357; --ink-mute: #5c6a80;
  --rule: #dde3ec; --steel-2: #f4f6f9;
  --navy: #102a5c; --blue: #2a6fdb; --blue-text: #1d5bbf;
  --mist: #f2f5fa; --mist-2: #e4eaf4;
  --gold: #b8862f; --gold-2: #e2bc72; --gold-soft: #f7efe1;
}
```

### 색 역할 (절제가 핵심)
| 색 | 쓰는 곳 |
|---|---|
| **남색** | 기본. 제목, 섹션 번호 배지, 섹션 제목, 표 머리글, 결론 상자 바탕 |
| **파랑** | "결과"에만. 흐름의 "결과" 칸, 결과 섹션 태그, 판정 카드 |
| **골드** | 결론과 "원인"에만. 결론 핵심 문구, 근거 카드, "그래서" 칸, "오차 원인" 태그·배지 |
| 연한 회청(mist) | 연구 질문 띠, 판정 카드, 표 줄무늬 |

골드를 여기저기 쓰면 결론이 묻힌다(실제로 지적받았음). 강조 포인트는 **결론 상자 → 연구 질문 흐름 → 핵심 결과 카드** 세 곳으로 좁힌다.

### 컴포넌트
- **섹션 제목:** `[남색 번호 배지] 제목 ....... [역할 태그]`. 아래에 얇은 회색 선과 짧고 굵은 남색 선을 겹친다.
- **역할 태그 4종(모양은 같고 색만 다름):** 방법(흰 바탕 + 남색 테두리) / 결과(파랑) / 원인(연한 골드) / 정리(남색). 한 종류만 다른 스타일로 남지 않게 주의한다.
- **헤더 개요 칩:** 저자 줄 옆에 "예비 연구 · 참가자 n명 · 조건 · 측정 방식" 같은 칩을 둔다. 높이를 늘리지 않고 빈 공간을 채운다.
- **정리 표:** 줄무늬 배경, 왼쪽 얇은 남색 띠, 원인 항목에 "원인 1·2·3" 배지, 개선 방향 앞에 `→`.
- **원리 그림:** 어려운 개념은 작은 인라인 SVG 그림 세 칸(정상 / 변화 / 오류 상황)으로 보여 준다. 따로 상자를 만들지 말고 관련 섹션 안에 넣는다.

### 타이포그래피
- 글꼴: `"Apple SD Gothic Neo", "IBM Plex Sans KR", "Malgun Gothic", sans-serif`.
- 한국어 줄바꿈: 본문 요소에 `word-break: keep-all`을 건다. 안 그러면 단어 중간에서 끊긴다("실패했습니/다").
- 한 단어만 다음 줄로 넘어가는 문장은 문장을 줄여서 해결한다.

### 간격
- 섹션 블록 사이 세로 간격을 **하나로 통일**한다(연구 질문 띠 → 3열, 3열 → 07, 07 → 결론 모두 110px).
- `.cols`에 `flex: 1`이 있으면 남는 높이가 전부 3열 아래에 쌓여 간격이 달라진다. `align-content: center`로 위아래에 나누고, 다음 섹션의 위 여백은 없앤다.
- 세 열의 높이가 비슷하도록 내용을 배치한다. 한 열이 짧으면 관련 그림을 넣어 채운다.

## 5. 작업 순서와 검증

1. **내용 먼저:** 데이터와 실험 기록 문서를 읽고 연구 질문, 4칸 흐름, 섹션별 핵심 문장, 근거 숫자 3개를 정한다.
2. **그래프:** Python으로 SVG를 생성해 인라인으로 넣는다(`charts.py` 참고). 색은 흰 배경 기준 M `#2a6fdb`, F `#b8741a`, 보조선 `#8a96a8`, 격자 `#dde3ec`. 범주 색을 고를 때는 dataviz 스킬의 `validate_palette.js`로 `--mode light` 검증을 통과시킨다.
3. **이미지:** 휴대폰 사진은 EXIF 회전값이 있어서 그대로 자르면 옆으로 누운 채 잘린다. Pillow `ImageOps.exif_transpose()`로 바로 세운 뒤 자르고, 긴 변 1200–1400px로 줄여 `assets/`에 저장한다.
4. **높이 측정 (수정할 때마다):** 임시 사본에 측정 스크립트를 붙여 헤드리스 Chrome `--dump-dom`으로 각 블록 높이를 읽는다. `.sheet`의 `height`를 `auto`로 바꾸고 각 블록의 `offsetHeight + margin`을 더한 값이 **5107 이하**여야 한다. 화면 맞춤용 `transform`이 걸린 상태에서 `getBoundingClientRect`를 쓰면 값이 틀리니 `#poster`의 transform을 먼저 해제한다.
   ```bash
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
     --window-size=3200,4600 --virtual-time-budget=4000 --dump-dom "file://$PWD/probe.tmp.html"
   ```
5. **PDF 생성:**
   ```bash
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
     --no-pdf-header-footer --print-to-pdf="<출력.pdf>" "file://$PWD/poster.html"
   ```
   PDF가 **1쪽**인지 확인한다(`/Type /Page` 개수).
6. **눈으로 확인:** `sips -s format png -Z 2400 <pdf> --out <png>`로 이미지를 만들어 직접 본다. 겹침, 넘침, 단어 중간 줄바꿈, 빈 공간, 색 과다를 확인한다. 세부는 4000px로 키워 잘라 본다.
7. **수정 전에 백업:** 큰 수정 전에는 `poster.html`을 scratchpad에 복사해 두고 되돌릴 수 있게 한다.
8. **Artifact 공유(선택):** doctype·html·head·body·charset·viewport 줄을 뺀 사본을 scratchpad에 만들어 publish한다. 새 이미지는 `files` 맵으로 함께 올린다.

## 6. 실제로 겪은 함정

| 증상 | 원인 | 해결 |
|---|---|---|
| 흐름 칸 안에 세로선이 보임 | 예전 디자인의 `.steps::before` 규칙이 새 요소의 같은 클래스 이름에 적용됨 | 클래스 이름을 새로 정함(`.flow`) |
| 태그 두 개만 배경이 없음 | 옛 `.u` 클래스가 남아 있었음 | 모든 태그를 `.qt` + 역할 클래스로 통일 |
| 흰 배경으로 바꾼 뒤 "흰 선은 세트 평균" 문구가 틀림 | 그래프 색만 바꾸고 설명문을 안 고침 | 테마를 바꾸면 본문의 색 언급도 검색해서 고침 |
| 3열 위아래 간격이 다름 | `flex: 1` 남는 높이가 아래에 쌓임 | `align-content: center` + 다음 섹션 위 여백 제거 |
| 1px 넘침 | 문장 한 줄 증가 | 작은 패딩을 줄이거나 문장을 줄임 |
| 사진이 옆으로 잘림 | EXIF 회전 | `exif_transpose` 후 자르기 |

## 7. 새 포스터를 시작할 때 체크리스트

- [ ] 결론 아래 근거 카드 3장이 본문 섹션 번호와 연결되는가
- [ ] 한계와 다음 실험이 적혀 있는가
- [ ] 흰 테마, 색 상자는 가장자리에서 안쪽으로 들였는가
- [ ] 골드는 결론·원인에만 썼는가
- [ ] 측정 합계 5107 이하, PDF 1쪽인가
